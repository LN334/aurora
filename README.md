Aurora 是一款音乐播放器。曲库来自网易云、QQ 音乐、酷狗、汽水账号，外加 B 站视频里的音频轨。五个平台在同一个列表里，以统一合并为设计思路。

播的时候按你排的音源顺序挑一个能放的。界面配色跟着当前封面走，首页是一堵能转的封面墙，点「漫游」进一条放不完的推荐流。

[English](README.en.md) · [下载](https://github.com/LN334/aurora/releases/latest) · [更新日志](CHANGELOG.md) · [问题反馈](https://github.com/LN334/aurora/issues)

## 几条取舍

- **多源合一，不是换来源换行。** 同一首歌在几家都有时只占一行，行上标出在哪几家能放；收藏的专辑与关注的艺人按名字合并，几个平台亮几颗色点。点进去放的是主平台那份，取流仍按音源顺序。
- **数据留在本机。** 曲库、歌单、播放历史、收听统计都存本地，没有遥测、没有崩溃上报。设置里能把它们打包成一个文件带走。
- **不绕过付费。** 能播的只有你账号本来就有权限播的。加密音频、会员音质、付费专辑都不碰，界面会直接说是哪种原因（需要会员 / 地区限制 / 只有试听 / 已下架）。
- **界面跟着封面走。** 颜色只来自当前封面，没有主题色设置项。深浅两套配色各自独立，壁纸在下面，玻璃在上面——正在播放条与底部播放条是**折射**玻璃（按边缘曲率把背景推一下），其余是磨砂。
- **自动行为要能解释。** 漫游只写「已听 N 首」不报总数——报总数会让一条流看起来像一份歌单；音质降档会写明「低于所选 SQ，上游没有更高档」。

## 下载

到 [Releases](https://github.com/LN334/aurora/releases/latest) 下载最新的 `Aurora-x.y.z-Setup.exe`。

| 文件 | 说明 |
| :--- | :--- |
| `Aurora-x.y.z-Setup.exe` | 安装版。默认装到当前用户目录，不需要管理员权限；手动双击走向导，可选安装位置 |
| 应用内更新 | 自动只负责检查，下载与安装由你按。装好新版后第一次启动会弹一次更新说明 |

- 安装包没有代码签名，Windows SmartScreen 会拦一次：点「更多信息」，再点「仍要运行」。个人开发者打包的软件基本都是这个状态。

## 功能

### 曲库与多源

- 五个平台的搜索、歌单、专辑、艺人、每日推荐，加本机文件夹，收进同一个曲库。不登录也能搜、能播免费歌，登录后才有每日推荐、红心、收藏与关注。
- 同一首歌只占一行，行上标出在哪几家能放；收藏专辑与关注艺人多平台同名合并，亮几颗色点就是几家有。
- 每日推荐：从你勾选的几家各要一批，按来源交错混成 30 首，一天之内不变。
- 推荐歌单 / 推荐专辑 / 最近新歌三块混排，各自「换一批」都真去平台再要一次。
- 本机音乐：扫描文件夹，读标签、内嵌封面和同目录 `.lrc`，认 14 种音频格式；之后只重扫改动过的文件。按歌曲、专辑、艺术家、文件夹四个栏目看，点专辑进详情按唱片原序排。
- 每个列表都能搜：我喜欢的、最近播放、本机音乐、歌单详情、收藏专辑、关注艺人。按歌名、歌手、专辑筛，右边写「命中数 / 总数」，随机与播放全部跟着筛后的结果走。
- 曲目详情页：封面、事实表与可点的歌词，下面接一段评论区——头像、昵称、相对时间、赞数与回复数，一次 20 条，翻到底点「加载更多」。四个在线平台都能读；发评论支持网易云、QQ 与酷狗（各自要先登录），网易云的赞也能点，汽水只能读。本机文件不显示这一块。

### 播放

- 播放条常驻底部：封面、标题、艺术家、进度、模式、上一首/播放/下一首；右侧是队列、调音台、一起听、桌面歌词、舞台，再往右是倍速、喜欢与音量。窄窗口按优先级收：≤1080 收掉后三个视图键，≤900 再收倍速与音质——播放控制永远居中，收掉的入口都有快捷键或别的页可进。
- 播放模式一颗键轮四档：顺序 → 列表循环 → 单曲循环 → 随机。
- **倍速 0.5–2×**：0.75 / 1 / 1.25 / 1.5 / 2 五档循环，播放页与底栏都能改，跟着偏好一起落盘，换歌时重新应用。
- **喜欢**：底栏与播放页各一颗，同一个落点规则——只有一个平台有这首歌就直接写，几个平台都有就先问落到哪家；写完提示「已收藏到网易云」这类具体落点。
- 音源优先级可排：同一首歌几家都有时，按你排的顺序挑第一个能放的，本机排最后。
- 音质按平台设档（网易云无损、QQ 与酷狗极高、汽水标准……），换档从下一首起生效，正在播的不中断。播放页在字幕行末尾写实际到手的档位，降档时变成强调色。
- 在线歌可以存到本地；听过的在线歌自动留一份（默认 2 GB，可改可关），再听同一首直接读盘。
- **调音台**（播放界面按 E）：十段推子、五组预设、双击归零、实时电平与峰值/削波读数。自己调出一条满意的曲线可以存成本机预设，之后一键切回；也能复制成一串分享码发给别人，粘贴就能还原。交叉淡化、ReplayGain 音量标准化与峰值限幅也在这一套里。
- 播放页：封面、可点的歌词、进度、音量浮层、模式、喜欢与倍速；副标题那行还写着队列位置（第几首 / 共几首）。控制行三段等分，播放键严格居中。

### 一起听

- 同一 WiFi 下开一个房间，别人用一条邀请链接进来，也可以照「地址 + 房间码」手填。房间码默认随机 6 位，房主可以改成自己好念的一串；还能再上一道密码，只发给要请进来的人——房间码是房间号，密码才是锁。
- **找房间**：同一个局域网里，客人只填房间码就会自己找到房（UDP 广播问一声，房主答一句），不必抄地址和端口。
- **跨网络**：房间页那颗「开公网」会用 Cloudflare 快速隧道把房间挂到一个 `wss://` 地址上——不用账号、不用备案。地址一出现就自动写进房间，断开自动撤回，退出应用时把隧道进程一起收掉；也可以自己填隧道地址（`域名:端口` 或 `wss://域名`）。
- **邀请链接**：`aurora://join/房间码?host=主机&secure=1`，房间码走路径、整条只有一个 `://`。发出去的是 https 落地页（`ln334.github.io/aurora/join/`）——微信、QQ、浏览器都能点开，页面上有房间码、「在 Aurora 中打开」与「复制地址+房间码」，内置浏览器拦自定义协议时会给出照做的退路。
- 安装版会注册 `aurora:` 前缀，点开链接直接开 Aurora 进房；加入失败（码不对、密码不对、连不上、HTTP 501/503）会停在入口页并说清原因，不会留一个没人的空房间。
- 音频各自取，网络里只走几百字节的「听什么、听到哪」。房主换歌或按暂停，房间里跟着变；位置按消息里的时间戳补齐，偏差过 3 秒才纠正一次，自己刚拖过进度的人 8 秒内不被打回去。
- 房间里还能说话、发表情，一条话由房主那边记账再广播，中途进来的人看得到最近几十条。

### 歌词

- 全屏歌词页：当前一句放大，上下按距离渐隐，原文一行、译文贴在其下；每一句都带译文，非当前句压暗。停手几秒自己回到正在唱的那句。
- 带词级时间标签的增强 LRC 会按词点亮（只改透明度，不动字号行高）。
- 点任意一行歌词跳到那个时间点。
- 桌面歌词：独立透明窗口，只显示当前一句（原文一行、译文一行小字），换歌自动跟上。鼠标移上去浮出胶囊工具条，移开淡掉。
- 锁定时鼠标穿透，但移上去照样能拖能点，不用先解锁。
- 主窗口全屏、进歌词舞台，或系统里有别的程序全屏（游戏、全屏视频）时，桌面歌词自动让开。

### 外观

- 首页：问候 + 每日推荐的封面墙（滚轮与拖动都能转，弹簧落位），然后是上次听到的那首、四个入口格子、三块推荐、最近的八张。
- 漫游：一条放不完的流，切一首补一首，不报总数；去听歌单或专辑会退出漫游并还原播放模式。歌只来自各平台自己的漫游流（网易云、QQ、汽水有私人漫游接口，酷狗的每日推荐就是它的漫游），不掺收藏、本机与播放历史。轨道上能切「默认 / 熟悉 / 探索」三种挑法：只改这一批先放谁，不会让平台换一批歌。
- 深浅两套主题，可跟随系统；界面颜色只来自当前封面。
- 动态背景：装了 Steam 版 Wallpaper Engine 就能用创意工坊的壁纸，场景（`.pkg`）、视频、网页、图片都行。场景包由主进程读出来交给引擎（144 MB 约 83 ms），画质分省电（20 帧）/ 均衡（30 帧）/ 清晰（60 帧）。壁纸工程里那些「组件参数」不列出来，只留能改画面的项。

### 设置与维护

| 分区 | 内容 |
| --- | --- |
| 播放与音质 | 交叉淡化、调音台、五个平台的音质档位、在线歌词 |
| 推荐来源 | 哪几个平台参与推荐 |
| 首页 | 首页各分区的显隐与顺序 |
| 外观与桌面 | 主题、背景（标准 / 轻薄亚克力）、模糊程度、跟随封面取色、桌面歌词、动态背景与壁纸库、壁纸画质 |
| 快捷键 | 全部键位一张表 |
| 下载 | 保存到、格式、码率、转码器、在线缓存上限与占用 |
| 启动与系统 | 开机自启、放歌时阻止休眠、点关闭按钮的行为 |
| 清理与维护 | 释放内存、垃圾文件、打开数据目录、备份与恢复 |
| 更新与关于 | 版本、检查频率、更新说明、反馈入口 |

- **清理与维护**：释放内存把空闲页面的内存还给系统，播放不中断；垃圾文件分缓存、日志、崩溃转储三类，日志与转储立刻删，缓存被 Chromium 占着就排进清单、下次启动先清。
- **备份与恢复**：导出一个 JSON，里面是设置、曲库、歌单、播放历史与收听统计。**登录状态不在备份里**——会话文件装的是各家平台的 cookie，换台机器本来也要重新登录。导入只认自己写过的文件名，导入前现有的四份文件会先整份挪进 `backup-before-restore/`；导完提示里多一颗「立即重启」。

### 系统集成

- 托盘常驻：默认关窗口只是收进托盘，音乐继续播；真正退出走托盘右键菜单。
- 任务栏缩略图按钮（上一首 / 播放暂停 / 下一首）、Windows 媒体控制面板、硬件媒体键。
- 系统媒体卡片上带当前曲目的封面，任务栏歌词条、媒体浮窗这类工具也能读到封面。
- 全局热键：`Ctrl+Alt+L` 桌面歌词、`Ctrl+Alt+K` 锁定、`Ctrl+Alt+Space` 播放暂停、`Ctrl+Alt+左右` 上下首、`Ctrl+Alt+上下` 音量。

## 音源

| 来源 | 状态 |
| --- | --- |
| 本机文件 | 可用，电脑上有音乐文件就行 |
| 网易云音乐 | 可用，不登录也能搜和播一部分 |
| QQ 音乐 | 可用，不登录只能播免费歌（会员歌拿不到），建议登录 |
| 酷狗音乐 | 可用（含概念版签名） |
| 汽水音乐 | 可用 |
| B 站 | 可用，把视频当歌听（DASH 音频轨，最高 192k），没有歌词；可扫码登录，登录后搜索不容易被人机验证挡下 |
| Spotify / Apple Music / Navidrome / Jellyfin | 未实现，代码里留了接入位置 |

五个平台都是**非官方接入，没有得到任何授权**。网易云走社区逆向接口 [NeteaseCloudMusicApiEnhanced](https://github.com/neteasecloudmusicapienhanced/api-enhanced)，QQ 音乐走 [@yakult-green-tea/qq-music-api](https://www.npmjs.com/package/@yakult-green-tea/qq-music-api)（[Rain120/qq-music-api](https://github.com/Rain120/qq-music-api) 的活跃分支，在主进程里当本地 Koa 服务跑），酷狗和汽水照着网页端与 App 的接口自己接。

由此带来的限制：

- 仅供个人学习自用。这类接口属于未授权访问，也违反平台服务条款。
- 随时可能失效。平台改版、风控升级都可能让它坏掉，账号也有被风控的风险。
- 不破解付费内容。加密音频、会员音质、付费专辑都不碰。
- 在线歌存到本地拿到的是平台这次给出的音源文件，能不能下到完整一首看账号与版权。

四家的官方开放接口都不面向个人桌面软件（QQ 音乐开放平台文档写明「暂不支持个人开发者申请接入」，接入终端只列移动应用、小程序、智能硬件与车载），所以只有逆向这一条路，风险自己判断。

未登录时能听到什么：

| | 网易云 | QQ 音乐 |
| --- | --- | --- |
| 搜索 | 可以 | 可以 |
| 免费歌曲 | 完整播放 | 完整播放（128k） |
| 会员歌曲 | 给试听片段 | 拿不到，点下去会说明原因 |
| 未登录可播比例（实测） | 免费曲整首，付费曲试听 | 293 首取样里 18.4% |

## 你的数据

默认什么都不上传，也没有遥测。需要联网的只有下面几处，多数要你主动触发；例外是首页的推荐歌单——打开首页会向平台要一次公开推荐，不需要登录。

- **音乐文件与索引**：全部在本机，不上传；每个档案各有一份文件夹列表与索引。
- **登录凭据**：用 Windows 的 DPAPI 加密后只存本机，明文不落盘、不进日志；每个档案一份，退出登录就清掉。
- **在线歌词**：优先读音频旁的 `.lrc`；本机没有且开着「在线歌词」（默认关）时才去 [lrclib.net](https://lrclib.net) 查，结果缓存在本机。在线曲目的歌词直接问它所在的平台。
- **在线缓存**：`%APPDATA%\aurora-player\media-cache`，默认上限 2 GB，超了按最久未听先删。
- **封面缓存**：`%APPDATA%\aurora-player\cover-cache`，上限 200 MB。
- **更新检查**：读 GitHub 公开接口，可以改成手动。
- **在线播放本身**：搜索词、你播的歌、账号 cookie 最终都会发到平台服务器。上面说的是 Aurora 自己怎么存，不是「用了就不联网」。

## 常见问题

**安装时被 Windows 拦了？** 安装包没有代码签名，点「更多信息」→「仍要运行」。

**不登录能听吗？** 能。免费歌不登录也能搜、能播；付费曲看账号权限。每日推荐、歌单、云盘要登录。

**某首歌提示播不了？** 界面会说是哪种原因，这是平台的权限判断，软件不会绕过它。

**扫描不到本地音乐？** 在侧栏底部「我的」里手动添加文件夹。加进去还没有内容时，界面会把正在扫描的路径列出来。

**点关闭按钮没退出？** 这是刻意的，关窗口只是收进托盘。真正退出走托盘右键菜单，或在设置里改成关闭即退出。

**换了账号，歌单没变？** 侧栏底部「我的」里切换档案。每个档案绑一套账号、文件夹和播放偏好。

**清理之后缓存占用没变？** GPU 与着色器缓存被 Chromium 占着删不掉，会记进待清理清单、下次启动先删。

**壁纸库说读不到壁纸？** 需要 Steam 版 Wallpaper Engine，并且创意工坊里下载过至少一张。

## 已知限制

- 四个在线平台都依赖第三方逆向接口，随时可能失效。
- 安装包没有代码签名。
- 歌词：四个平台能取词（B 站没有，视频里没有结构化歌词），译文是平台自带的另一条轨（网易云 `tlyric`、QQ `trans`、酷狗 KRC 里的 `language` 轨、汽水 `lang_translations`），主进程把它并到原文行上、界面再拆成两行。逐字只对带词级时间标签的增强 LRC 生效，四家接口都只给整行时间（网易云的 `yrc` 实测为空）。
- 系统级全屏检测靠一个常驻 PowerShell 进程读 `SHQueryUserNotificationState`，只在桌面歌词开着时运行。
- 大曲库第一次扫描要把每个文件的元数据读一遍，之后增量重扫很快。
- 均衡器是 10 段固定频点，不是参数均衡。
- 动态背景只支持 Windows，要求本机装了 Wallpaper Engine。
- 界面只有中文；音质、外观、快捷键这些设置是设备级的，不跟档案走。
- 关注艺人里 QQ 与酷狗的艺人没有可打开的详情页（平台协议里没有这个接口），卡片不抬升、鼠标悬停会说明。

### 代码结构

```
src/app/            外壳：路由、侧栏、标题栏、跨功能 hook
src/features/       功能模块：accounts discover downloads favorites glass kugou library lyrics netease online overlay perf player playlists qishui qq refs settings updates wallpaper
src/views/          页面与面板
src/ui/             共享基元：卡片、封面、图标、列表、时间格式化
src/stage/          歌词页与可视化
electron/pure/      零 Electron 依赖、可以在裸 Node 下测试的纯逻辑
electron/protocols/ 私有协议：aurora-app / aurora-media / aurora-remote / aurora-wallpaper / aurora-cache
electron/ipc/       通用 IPC：播放器、库、歌词、设置、更新、壁纸、下载、悬浮窗
electron/netease/   网易云接口、会话、IPC
electron/qq/        QQ 音乐接口、会话、传输、本地服务
electron/kugou/     酷狗接口、会话、签名
electron/qishui/    汽水接口、会话
```

依赖方向单向：`views → features → ui`。`electron/pure` 不依赖其它 electron 模块，否则测试里加载不了。

技术栈：Electron 44、React 19、TypeScript 5、Vite 7、Zustand 5、music-metadata。没有 UI 组件库、没有图标库（图标是手写 SVG）、没有 CSS 框架。

界面上有几条固定规则：一页只有一个标题（由外壳打）；本地与在线共用同一套卡片；不在页内另造侧栏；颜色只来自封面。配色写在 `src/styles/tokens.css`，完整记录见 [docs/ui-design.md](docs/ui-design.md) 与 [docs/architecture.md](docs/architecture.md)。

### 加一个平台

音源接缝在 `src/features/library/source.ts` 的 `TrackSource`：

```ts
id / name / summary / online / streamUrl(track) / artUrl(track) / lyrics(track)
```

播放内核不假设「歌一定在磁盘上」。现在实现了 `localSource` 与 `neteaseSource`，其它三家走 provider 层。

两个必须遵守的约束：`artUrl` 必须同源或带 CORS 头（否则封面进不了 Canvas 取色）；音频要经主进程代理（`aurora-remote:`），渲染层的 CSP 只放行私有协议，代理顺带做 Range 转发与地址白名单。

账号侧在 `src/features/accounts/providers.ts`。状态不是 `ready` 的平台不会出现在界面上。

### 测试

`npm test` 跑 674 个用例，覆盖不依赖 Electron 的纯逻辑：LRC 解析（含行内词级时间）、更新日志解析、歌词匹配打分、m3u 编解码、队列推进、文件夹树、版本比较、档案隔离、协议路径校验、扫描节流、在线缓存淘汰与 Range 解析、封面缓存预算、本机库排序、书架合并与搜索、播放统计、备份包校验、壁纸选择与画质换算。

界面有真实窗口巡检验证：`npm run smoke` 用 Electron 起独立窗口（独立 user-data-dir，不动你正在用的配置），从侧栏逐页点过去，收集控制台报错、破图与未捕获异常。带 `--library` 时它自己造三首静音曲和配套歌词，先收藏再播一遍，所以「我喜欢的」与「最近播放」是真实数据而不是空态；设置页会走完九个分区并真的点一次清理扫描。任何一步失败都以退出码 1 结束，截图留在 `shots/smoke/`。

三个审计脚本接在 `npm run check` 里：可达性、CSS 死选择器、指向已不存在文件的路径引用。

这组测试抓到过两个真问题：按文件夹播放会连带播同前缀的兄弟目录（`C:\Music` 匹配到 `C:\Music2`）；IPv4 伪装成 IPv6 的 SSRF 绕过。

### 性能

单核百分比。任务管理器显示的是全机占用，除以逻辑核心数即可。

| 场景 | 单核忙时 | DOM 变更/秒 |
| --- | --- | --- |
| 空白页对照 | 0.72% | 0 |
| 空闲（暂停） | 0.73% | 0 |
| 前台播放，无歌词页 | 2.05% | 17.5 |
| 前台播放 + 歌词页 | 5.74% | 28.6 |
| 窗口隐藏 | 0.16% | 1.7 |

大曲库（5000 首）：55,209 个 DOM 节点，JS 堆 29 MB，滚动帧间隔 p95 17 ms，不需要虚拟化。主进程启动链 37.9 ms、常驻 1.04 MB；网易云上游包首次加载 1492 ms / 29 MB，懒加载，启动不付这个成本。

同产物连跑抖动约 ±0.3pp，差异小于 0.5pp 不要当成优化。口径见 [docs/perf-baseline.md](docs/perf-baseline.md)。

### 发版

```bash
# 1. 改 package.json 的 version（更新检查拿它和远端 Release 比）
# 2. 打包
npm run dist
# 3. 提交、打 tag、推送
git add -A
git commit -m "release X.Y.Z"
git tag vX.Y.Z
git push && git push origin vX.Y.Z
```

然后在 GitHub 建 Release，把三个文件拖进附件区：

```
release/Aurora-X.Y.Z-Setup.exe
release/Aurora-X.Y.Z-Setup.exe.blockmap
release/latest.yml
```

`latest.yml` 不能漏，自动更新只读它。安装包没签名，Release 正文里附一行 SHA256 方便下载后自查。更新检查读的仓库地址来自 `package.json` 的 `repository.url`（electron-builder 打包时会剥掉 `build` 字段，运行时代码不能读 `build.publish`）。
