# Aurora

Windows 上的桌面音乐播放器，不带音乐内容。来源是本机文件夹，加上你登录的网易云、QQ 音乐、酷狗、汽水。同一首歌在几个平台都有时只占一行，点播放时按你排的音源顺序挑一个能放的。窗口配色跟着当前封面走。

## 功能

- 本机音乐：扫描文件夹，读标签和内嵌封面，认 14 种音频格式
- 四个在线平台：网易云、QQ 音乐、酷狗、汽水。不登录也能搜、能播免费歌，登录后才有每日推荐和红心
- 同一首歌只占一行，播的时候按音源顺序挑能放的那家
- 在线歌可以存到本地
- 全屏歌词页，配色取自当前封面
- 桌面歌词：独立透明窗口，浮在别的窗口上面，可以锁定穿透
- 播放队列、10 段均衡器、交叉淡化、音量标准化
- 装了 Wallpaper Engine 可以拿创意工坊的壁纸当背景，场景、视频、网页、图片都能用
- 托盘常驻、任务栏缩略图按钮、Windows 媒体控制面板、硬件媒体键

## 下载与安装

到 [Releases](https://github.com/LN334/aurora/releases/latest) 下载最新的 `Aurora-x.y.z-Setup.exe`。

系统要求 Windows 10 或 11，64 位。

安装包没有买代码签名证书，Windows 会拦一次：点「更多信息」，再点「仍要运行」。个人开发者打包的软件基本都是这个状态。

## 第一次打开

首次启动会自己去找你电脑里的音乐目录（通常是用户目录下的「音乐」），找到就开始扫描。找错了，或者想换成别的盘，在侧栏底部的「我的」里手动添加文件夹，下次不会自作主张改回来。

想听在线内容：在顶部搜索框里输入歌名回车，结果页顶上切到想去的那家。搜索不用登录。

## 音源

| 来源 | 状态 |
| --- | --- |
| 本机文件 | 可用，电脑上有音乐文件就行 |
| 网易云音乐 | 可用，不登录也能搜和播一部分 |
| QQ 音乐 | 可用，不登录多数歌只能试听，建议登录 |
| 酷狗音乐 | 可用 |
| 汽水音乐 | 可用 |
| Spotify / Apple Music / Navidrome / Jellyfin | 未实现，代码里留了接入位置 |

音乐有版权，播放器拿不到曲库本身。所以只有两条路：用你自己账号的权限，或者读你自己的文件。绕过平台付费和授权的那条路这里没有。

## 平台接口

四个平台都是**非官方接入，没有得到任何授权**。网易云走社区逆向接口 [NeteaseCloudMusicApiEnhanced](https://github.com/neteasecloudmusicapienhanced/api-enhanced)，QQ 音乐走 [qq-music-api](https://github.com/Rain120/qq-music-api)，酷狗和汽水照着网页端和 App 的接口自己接。

由此带来的限制：

- 仅供个人学习自用。这类接口属于未授权访问，也违反平台服务条款
- 随时可能失效。平台改版、风控升级都可能让它坏掉，账号也有被风控的风险
- 不破解付费内容。加密音频、会员音质、付费专辑都不碰。能播的只有你账号本来就有权限播的
- 在线歌可以存到本地，但拿到的是平台这次给出的音源文件。能不能下到完整一首看账号和版权，只能试听的会标出来

四家的官方开放接口都不面向个人桌面软件。QQ 音乐开放平台文档写的是「暂不支持个人开发者申请接入」，接入终端只列了移动应用、小程序、智能硬件和车载，没有 PC 桌面；条款还要求独立专区、品牌露出、上报听歌流水。网易云开放平台同样只面向合作方。只能走逆向接口，风险自己判断。

### 未登录能听到什么

| | 网易云 | QQ 音乐 |
| --- | --- | --- |
| 搜索 | 可以 | 可以 |
| 免费歌曲 | 完整播放 | 完整播放（128k） |
| 会员歌曲 | 给试听片段 | 拿不到，点了没有反应 |
| 未登录可播比例（实测） | 免费曲整首，付费曲试听 | 293 首取样里 18.4% |

QQ 音乐的数字是实测的：热门的歌基本都是付费曲（`payplay === 1`），未登录一律返回 `result=104003`。所以用 QQ 音乐建议先登录，否则多数歌点下去只会看到一句原因。

权限不够时界面会说明具体原因（需要会员 / 地区限制 / 只有试听 / 已下架 / 请求太频繁 / 网络问题），不会只丢一句「播放失败」。

## 界面

### 导航

左侧一列：

| 位置 | 项 |
| --- | --- |
| 顶部 | 推荐、漫游 |
| 我 | 我喜欢的音乐、最近播放 |
| 库 | 歌单、专辑、艺人、本机 |
| 底部 | 设置、我、收起侧栏 |

「库」的前三项问的是平台账号：歌单是四个账号里的单子，专辑是平台里收藏的专辑，艺人是网易云里关注的艺人。最后一项「本机」问磁盘上的文件，本地的歌、专辑、艺人收在那一页的标签里。

平台不单独占一级入口，四个平台和本机文件在同一个曲库里。

搜索只有顶部一个入口，`Ctrl K` 聚焦。回车进结果页，页内再切平台，不再放第二个输入框。

侧栏底部的「我的」进账号页：本机档案（谁在用）、每个档案绑的在线账号、本地音乐文件夹。

### 推荐

打开应用落在这里。最上面一句问候和今天听了多少，接着是上次听到的那首，四个格子分别进我喜欢的音乐、最近播放、歌单、我的收藏。

再往下是「今天听什么」：从你最近听的歌里按当天日期挑 30 首，明天换一批。

然后是三块推荐，各自都能「换一批」：

- **推荐歌单**：各平台混排，两行六列，按来源交错排，不让池子大的那家占满整排。
- **推荐专辑**：一行横条、共 12 张，左右箭头翻页。刻意不做成封面墙——上面歌单已经是三行六列的方卡了，两堵同形的墙并排放着看不出区别；这里用小方图在左、专辑名与艺人在右的横条，和歌单拉开形状上的差。一屏露四张，剩下的横着藏，翻页按一屏走。数据来自三处——网易云的新碟榜，QQ 与酷狗的新歌榜里抽出来的专辑；同一张专辑在几家都有时合并成一张卡，来源写在艺人后面。标题旁边那行小字写着这一批来自哪几家。
- **最近新歌**：四十首，左边一张主推大卡、右边九行一屏的紧凑列表，剩下的往下滚。首页上下已经有四段封面墙，这一块单独分成两栏，用主次拉开节奏，不再多铺一堵墙。三家混排，同一首在两家榜单上都出现时并成一行。

这几块的「换一批」都真去平台上再要一次：网易云的新碟榜按页码往后翻，QQ 与酷狗的榜单没有页码，就重取一遍、在取回的池子里轮转，所以连点两次不会是同一屏。

再往下是最近听过。

听歌记录只存本机：按天累计时长和曲目，最近 60 条，三分钟内重复播放不算两条。暂停、切歌、关窗口时落盘，拖进度条不算。

### 我的

我喜欢的音乐把各平台的红心放在一起，页头按平台给数量，每行标出这首歌在哪几家能放。

歌单页按平台分组，自己建的在上，从平台拉下来的在下面，新建时选建在哪家。一首歌在不在歌单里，和它在哪个目录、来自哪个平台无关，所以同一张歌单可以同时装本地歌和在线歌。歌单支持新建、重命名、删除、拖拽排序（也能用 `Alt+方向键`），可以导入导出 m3u / m3u8，导入时会告诉你多少条在曲库里找不到。

本机音乐读硬盘上的文件。扫描时读标签、内嵌封面和同目录的 `.lrc`，之后只重扫改动过的文件。里面分歌曲、专辑、艺术家、文件夹四个栏目，点专辑进详情，按唱片原序排。

### 播放

播放条常驻底部：封面、标题、艺术家、进度、上一首 / 播放暂停 / 下一首，右边是随机、循环、队列、均衡器、桌面歌词和音量。音量滑杆可以用滚轮微调，每格 5%；音量拖到 0 之后点静音键取消静音，会回到 60% 而不是继续没声。

点封面进全屏歌词页：当前一句放大，上下几行按距离渐隐。没有歌词时显示封面和歌名，可以联网查一遍。

- 十段均衡器，5 组预设，双击推子归零
- 交叉淡化：切歌时前一首淡出、后一首淡入，时长可调
- ReplayGain 音量标准化，峰值限幅，不会削波
- 队列面板按实际播放顺序显示，可点击跳转、可移除
- 「下一首播放」在右键菜单和列表右侧的 `⋯` 里

### 桌面歌词

独立窗口，只有歌词本身，没有底板。鼠标移上去浮出一条胶囊工具条：上一首、播放暂停、下一首、锁定、关闭，移开就淡掉。

锁定时鼠标穿透，不会挡住下面的窗口，但鼠标移上去照样能拖动和点按钮，不用先解锁。

### 系统集成

- 托盘：默认关闭窗口不退出，音乐继续播；设置里可以改成关闭即退出。真正退出走托盘右键菜单
- 任务栏缩略图按钮：上一首 / 播放暂停 / 下一首
- Windows 媒体控制面板和硬件媒体键
- 系统媒体卡片上带当前曲目的封面：封面会先转成图片数据再交给系统，所以任务栏歌词条、媒体浮窗这类读系统音乐信息的工具也能显示封面，而不是一个音符占位

## 设置

一个页面，左边一列分区：

| 分区 | 内容 |
| --- | --- |
| 播放与音质 | 交叉淡化、均衡器开关、四个平台的音质档位、在线歌词 |
| 推荐来源 | 哪几个平台参与推荐 |
| 下载 | 保存到、格式、码率、转码器 |
| 外观与桌面 | 桌面歌词字号、动态效果、Wallpaper Engine 动态背景与壁纸库、壁纸工程可调项、壁纸画质、壁纸可见度、全屏、关闭按钮行为 |
| 启动与系统 | 开机自启、放歌时阻止系统休眠、点关闭按钮时 |
| 快捷键 | 全部键位一张表 |
| 清理与维护 | 释放内存、垃圾文件、数据目录 |
| 更新与关于 | 版本、检查频率、自动下载安装、数据目录、GitHub |

设置项只有三种形态：开关、分段按钮、滑杆。左边标签，中间一行说明，右边控件。

**动态背景**需要本机装了 Steam 版 Wallpaper Engine，并且创意工坊里至少下载过一张。场景壁纸（`.pkg`）由内置的 WebGL 场景引擎渲染，和 Wallpaper Engine 里看到的是同一份工程；视频、网页、图片壁纸直接播放。软件只读它的配置和壁纸目录，不启动也不修改它。「跟随当前壁纸」会跟着你换的那张走，也可以钉死一张。壁纸画质分省电（20 帧）、均衡（30 帧）、清晰（60 帧，按屏幕物理像素渲染但压了像素总量上限）。

**清理与维护**里点「释放内存」会把当前用不到的页面内存交还系统，播放不中断。垃圾文件分缓存、日志、崩溃转储三类：日志和崩溃转储立刻删掉；缓存（GPU、着色器）在播放器运行期间被 Chromium 占着，Windows 不允许真正删除，所以会排进清单，下次启动、窗口还没建起来的时候先清。那一行写的「下次启动再清」就是这个意思。

## 你的数据

默认状态下什么都不上传，也没有遥测。需要联网的只有下面几处，多数要你主动触发。例外是首页的推荐歌单：打开首页时会向平台要一次公开推荐，不需要登录。

- **音乐文件和索引**：全部在本机，不上传；每个档案各有一份文件夹列表和索引
- **登录凭据**：用 Windows 自带的 DPAPI 加密后只存本机，明文不落盘、不进日志；每个档案一份，退出登录就清掉
- **在线歌词**：优先读音频旁边的 `.lrc`。本机没有时，开着「在线歌词」（默认关）才去 [lrclib.net](https://lrclib.net) 按歌名和艺术家查，结果缓存在本机。在线曲目的歌词直接问它所在的平台，不走 lrclib
- **更新检查**：读 GitHub 公开接口，不上报使用数据，可以改成手动
- **在线播放本身**：搜索词、你播的歌、账号 cookie 最终都会发到平台服务器。上面说的是 Aurora 自己怎么存，不是「用了就不联网」

没有遥测，没有使用统计，没有崩溃上报。

## 常见问题

**安装时被 Windows 拦了？**
安装包没有代码签名，点「更多信息」→「仍要运行」。

**不登录能听吗？**
能。免费歌不登录也能搜、能播。付费曲看你自己账号的权限，所以要登录；每日推荐、歌单、云盘也是登录后才有。

**某首歌提示播不了？**
界面会说是哪种原因。这是平台的权限判断，软件不会绕过它。

**扫描不到本地音乐？**
在侧栏底部的「我的」里手动添加文件夹。加进去之后如果还是什么都没有，界面会把正在扫描的路径列出来，这样能看出是路径选错了还是那个文件夹确实没歌。

**点关闭按钮没退出？**
这是刻意的。关窗口只是收进托盘，音乐继续播。真正退出走托盘右键菜单。

**清理之后缓存占用没变？**
GPU 和着色器缓存在播放器运行时被占用，删不掉。软件会把它们记进待清理清单，下次启动时先删。日志和崩溃转储不受影响，点了立刻清空。

**「壁纸库」说读不到壁纸？**
需要 Steam 版 Wallpaper Engine，并且创意工坊里下载过至少一张。

**换了网易云账号，歌单没变？**
侧栏底部的「我的」进账号页，切换档案。每个档案绑一个账号，歌单、收藏、音乐文件夹和播放偏好都跟着档案走。

## 已知限制

- 四个在线平台都依赖第三方逆向接口，随时可能失效
- 安装包没有代码签名
- 本地文件的歌词只查 lrclib；在线曲目用所在平台的歌词，酷狗和汽水没有歌词接口
- 大曲库第一次扫描要把每个文件的元数据读一遍，慢；之后增量重扫很快
- 均衡器是 10 段固定频点，不是参数均衡
- 深色背景上的 Canvas 径向渐变有轻微色带，没做抖动
- 动态背景只支持 Windows，要求本机装了 Wallpaper Engine
- 界面只有中文
- 音质、外观、快捷键这些设置是设备级的，不跟档案走

### 环境

Node.js 22 或更新版本。

```bash
npm install
npm run dev        # 开发模式：热更新 + Electron 窗口
npm test           # 纯逻辑测试，不需要 Electron
```

国内网络下 `npm install` 可能卡在下载 Electron 二进制。在项目根目录建一个 `.npmrc`（这个文件有意没有提交，它会强制所有克隆的人走第三方镜像）：

```ini
registry=https://registry.npmmirror.com
electron_mirror=https://npmmirror.com/mirrors/electron/
```

### 代码结构

```
src/app/            外壳：路由、侧栏、标题栏、跨功能 hook
src/features/       功能模块：accounts library lyrics netease online player playlists settings wallpaper home discover favorites qq
src/views/          页面与面板
src/ui/             共享基元：卡片、封面、图标、列表、时间格式化
src/stage/          歌词页与可视化
electron/pure/      零 Electron 依赖、可以在裸 Node 下测试的纯逻辑
electron/protocols/ 私有协议：aurora-app / aurora-media / aurora-remote / aurora-wallpaper
electron/netease/   网易云接口、会话、IPC
electron/qq/        QQ 音乐接口、会话、传输
electron/kugou/     酷狗接口、会话、签名
electron/qishui/    汽水接口、会话
```

依赖方向单向：`views → features → ui`。`electron/pure` 不依赖其它 electron 模块，否则测试里加载不了。

技术栈：Electron 44、React 19、TypeScript 5、Vite 7、Zustand 5、music-metadata。没有 UI 组件库，没有图标库（图标是手写 SVG），没有 CSS 框架。

界面上有几条固定规则：一页只有一个标题（由外壳打）；本地与在线共用同一套卡片；不在页内另造侧栏；颜色只来自封面。配色写在 `src/styles/tokens.css` 里，改界面时看它，别照截图。完整记录见 [docs/ui-design.md](docs/ui-design.md) 和 [docs/architecture.md](docs/architecture.md)。

### 加一个平台

音源接缝在 `src/features/library/source.ts` 的 `TrackSource`，成员七个：

```ts
id / name / summary / online / streamUrl(track) / artUrl(track) / lyrics(track)
```

播放内核不假设「歌一定在磁盘上」，音频、封面、歌词从哪来全部经过这个接口。现在实现了 `localSource` 和 `neteaseSource`。

两个必须遵守的约束：

1. `artUrl` 必须同源或带 CORS 头，否则封面进不了 Canvas 取色
2. 音频要经主进程代理（`aurora-remote:`），渲染层的 CSP 只放行私有协议。代理顺带做 Range 转发和地址白名单，拒绝指向本机和内网的地址

账号侧的位置在 `src/features/accounts/providers.ts`，`ProviderId` 里有 `subsonic`、`lastfm`、`listenbrainz`、`spotify`、`apple`，每条写明了需要什么（密码 / token / OAuth）和当前状态。状态不是 `ready` 的平台不会出现在界面上。

### 测试

`npm test` 跑 482 个用例，覆盖不依赖 Electron 的纯逻辑：LRC 解析、m3u 编解码、队列推进、文件夹树、版本比较、档案隔离、协议路径校验、扫描节流、网易云相关纯函数、搜索默认来源、来源标签规则、壁纸选择与画质换算、播放历史按日累计。

界面有真实窗口巡检验证：`npm run smoke` 用 Electron 起一个独立窗口（独立 user-data-dir，不动你正在用的配置），从侧栏逐页点过去，收集控制台报错、破图和未捕获异常，然后联网搜一次、点开一首在线歌确认播放条真的走过了 0:00。装了 Wallpaper Engine 时还会真的选一张壁纸，确认背景挂上了场景 canvas 并连拍两帧确认它在动。任何一步失败都以退出码 1 结束，截图留在 `shots/smoke/`。

三个审计脚本接在 `npm run check` 里：可达性（从真实入口走 import 图找无法加载的文件）、CSS 死选择器、指向已不存在文件的路径引用。

这组测试抓到过两个真问题：按文件夹播放会连带播同前缀的兄弟目录（`C:\Music` 匹配到 `C:\Music2`）；IPv4 伪装成 IPv6 的 SSRF 绕过。

### 性能

单核百分比。任务管理器显示的是全机占用，除以逻辑核心数即可。

| 场景 | 单核忙时 | DOM 变更/秒 |
| --- | --- | --- |
| 空白页对照 | 0.72% | 0 |
| 空闲（暂停） | 0.73% | 0 |
| 前台播放，无歌词页 | 2.05% | 17.5 |
| 前台播放 + 歌词页 | 5.74% | 28.6 |
| 窗口隐藏 | 0.16% | 1.7 |

大曲库（5000 首）：55,209 个 DOM 节点，JS 堆 29 MB，滚动帧间隔 p95 17 ms，超过 33 ms 的帧 0 个，不需要虚拟化。

主进程启动链 37.9 ms、常驻 1.04 MB。网易云上游包首次加载 1492 ms / 29 MB，是懒加载的，启动不付这个成本。

同产物连跑抖动约 ±0.3pp，差异小于 0.5pp 不要当成优化。口径见 [docs/perf-baseline.md](docs/perf-baseline.md)。

### 发版

```bash
# 1. 改 package.json 的 version（更新检查拿它和远端 Release 比）
# 2. 打包
npm run dist
# 3. 提交、打 tag、推送
git add -A
git commit -m "release X.Y.Z"
git tag vX.Y.Z
git push && git push origin vX.Y.Z
```

然后在 GitHub 建 Release，把三个文件拖进附件区：

```
release/Aurora-X.Y.Z-Setup.exe
release/Aurora-X.Y.Z-Setup.exe.blockmap
release/latest.yml
```

`latest.yml` 不能漏，自动更新只读它。应用内「检查更新」走 GitHub Releases API，是另一条路。

安装包没签名，所以 Release 正文里附一行 SHA256，下载后可以自己对：

```powershell
Get-FileHash release/Aurora-X.Y.Z-Setup.exe -Algorithm SHA256
```

更新检查读的仓库地址来自 `package.json` 的 `repository.url`。注意 electron-builder 打包时会剥掉 `build` 字段，运行时代码不能读 `build.publish`。
