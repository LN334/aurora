# 一起听 · 完整方案

> 这份文档描述「一起听」这一整套东西：谁做什么、数据怎么走、三个页面各管什么、哪些已经做完、哪些卡住了。界面细节放在最后——先把链路说清楚。

## 一、目标

两个人在两台机器上听同一首歌，进度对齐，能聊天。房主的音质就是全房间的音质。

不做的事：不做官方房间（酷狗/网易云的房间服务），不替平台做版权分发。

## 二、两种角色

| | 房主 | 客人 |
|---|---|---|
| 开房 | 开一个房间，拿到房间码 | — |
| 进房 | — | 地址 + 房间码 |
| 音频 | 由他取流，可选转发给全房间 | 有账号就自己取，没账号用房主转发的 |
| 公网 | 需要时开樱花隧道 | 不需要 |

房间活在**主进程**里，不活在页面里：关掉界面不等于退房，重新进来还在同一间。

## 三、链路

```
房主                          房间（主进程）                客人
 │                               │                          │
 ├─ 开房 ──────────────────────► │ 监听端口，生成 6 位房间码  │
 │                               │ ◄──── 地址 + 房间码 ──────┤
 │                               ├─ 校验房间码，建立长连接 ──►│
 │                               │                          │
 ├─ 播放变化（自动）────────────► │ 广播「现在放什么、第几秒」►│
 │                               │                          ├─ 跟随
 │                               │ ◄──────── 聊天 ──────────┤
 │                               ├──────── 转发聊天 ───────►│
 │                               │                          │
 ├─ 关界面（房间仍在）           │                          │
 └─ 离开房间 ──────────────────► │ 解散 / 移除成员           │
```

「现在放什么」**不是靠按钮同步的**：播放一动（换歌、暂停、拖进度）就自动上报，房间里其他人跟着走。所以界面上没有「同步我现在这首」这颗键——它本来就不该存在。

## 四、音频怎么到客人耳朵里

两条路：

1. **平台直链**：客人自己有账号，用房主给的链接自己取流，音质由他自己的账号决定。
2. **房间转发**：房主替全房间取流，再经房间端口转发出去。客人没账号也能听到同一档。转发可以关（房间面板里那个勾），关了之后没账号的客人就听不到——这是一个明确的取舍，不是 bug。

转发用房间自己的 HTTP 端口（`/stream/<token>`），token 随机、按歌复用，每个客人最多同时开 2 条流，超了回 429 让他等——避免一个人把房主的带宽吃光。

## 五、公网：樱花隧道

同一个 WiFi 直接填局域网地址就行。跨网络要让房主把房间端口穿到公网。

这一套做成独立的一页（**樱花隧道**），和房间分开——房间管听什么，它管怎么穿出去。

步骤（全部由程序推着走，不需要用户抄路径、抄密钥）：

1. **登录**：页面里一颗「登录樱花」，开内嵌登录窗，登录完密钥自己带回来。
2. **找 frpc**：程序自己去下载目录/桌面/文档/安装目录找 `frpc*.exe`，找到就用。
3. **拉隧道列表**：进页面自动拉，一张隧道一张卡（ID / 节点 / 映射 / 开关）。
4. **绑定端口**：点某张卡的开关，房间会**改成那条隧道指向的本地端口**再重开，然后起 frpc。

第 4 步的方向是反的：隧道里的本地端口写死在樱花服务端，改它要动用户的隧道配置（那条隧道可能还给别的服务用）。房间是自己的，让它监听那个端口，两边天然对上。

## 六、三个页面

| 页面 | 管什么 | 入口 |
|---|---|---|
| 一起听 | 开房、加入、房间信息、成员、正在放 | 播放条「一起听」 |
| 樱花隧道 | 登录、frpc、隧道卡片、启停 | 房间页「樱花隧道」 |
| 聊天 | 消息流、输入、快捷表情 | 房间页「聊天室」 |

一页一个标题，标题由外壳打。页内不再套弹窗——之前做成浮在中间的弹窗，内容被挤成一小块，是这个功能反复返工的原因之一。

一起听时的**播放页**还应该和普通播放页不同，三个候选：

- **A 顶部房间条**：顶上一条 `● 房间 J8H95P · 2 人 · 已同步`。只加信息，不改布局。
- **B 封面挂徽章**：封面角上一枚 `● 一起听`，右下角成员头像。最省地方。
- **C 双游标进度**：进度条上再加一根房主的位置线，底下写「差 8 秒」+「对齐」键。

倾向 **C**：一起听最怕的不是「不知道在房间里」，而是「两个人听着不一样、且看不出来」。

## 七、现在到哪一步了

**能用**

- 房间：开房、加入、成员、正在放（带封面）、自动跟随、转发开关、离开房间
- 转发：`/stream/<token>`、每客户端 2 条上限、上游 Referer/UA 透传
- 三页结构：一起听（入口 / 房间）、樱花隧道、聊天
- 樱花：进页自动拉列表、卡片启停、房间端口反向绑定、frpc 自动查找、密钥存本机
- 播放页顶上一条「一起听」：房间码、成员、在放什么、公网地址、回房间
- 房间有人时不重开：点隧道开关会先说「还有 N 位听众，改端口会让他们掉线」，不静默踢人

**待办**

1. **登录链没实测**。樱花走 Nyatwork OpenID：登录在另一个域名，跳回面板才有「复制访问密钥」。
   代码已改成「回到 `natfrp.com` 再找按钮、点它、连读 6 轮剪贴板」，但没有账号验证过。
   这条不通就退到「手动粘一次密钥、之后永久记住」——一次性成本，换掉不确定性。
2. **打包版**：仍然是好的，但**不能在 `D:\Aurora` 这棵树下面跑**——这棵树里任何 Electron
   可执行文件都在启动时崩 `0x80000003`，崩在 JS 之前（连 `boot-marker` 的一行都没写）。
   同一个 `app.asar` 用开发版 electron 加载能跑；同一份打包产物拷到 `D:\` 根下能跑。
   在这台机器上验打包版，**一律先拷出项目目录再跑**。
3. **房间端口绑定后房间会重开一次**——现在有提示、不静默做了；更理想是让在场的人自动重连。
