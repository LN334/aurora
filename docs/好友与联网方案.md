# 好友与联网系统的完整方案

> 一起听现在是「一个房间 + 一份广播」。「好友」要在这个之上加一层**人的状态**。
> 这份文档说清：谁是谁、各自知道什么、哪些做得到、哪些在没有服务器的情况下做不到。

## 一、先说清一件硬事：我们没有服务器

Aurora 是纯客户端，房间里只有房主的机器在监听。所以：

| 想做的事 | 有没有服务器 | 能不能做 |
|---|---|---|
| 和同一房间里的人成为好友 | 不需要 | ✅ 房间里就能加 |
| 看到好友在不在线 | 不需要 | ✅ 只要他最近和你在同一个房间出现过 |
| 给他推一条邀请（他不在任何房间） | **需要** | ❌ 没有地方转这封信 |
| 跨房间的好友聊天 | **需要** | ❌ 同上 |

方案里凡是要「服务器」的功能都不假装能做：界面上不给入口，而不是给了入口再失败。

## 二、四层结构

```
身份 identity      我在这台机器上是谁        uuid，存本机        ✅ 已有
在线 presence      他现在在听什么、能听什么  随房间广播         ⬜ 待做
好友 friend        我把他记下来了            本地一份表         ⬜ 待做
联网 network       房间、长连接、公网       room.ts            ✅ 已有
```

身份是**主键**，presence 是**值**，好友是**关系**。三层各有各的存储，不混在一起。

## 三、身份（已完成）

- 首次进房生成 UUID，存 `%APPDATA%\aurora-player\party-identity`；
- 每次进房在 `hello` 里带上它；
- 房主认得这个 id 就复用，不认得（旧客户端）退回随机。

这条是地基：没有稳定 id，好友表存的东西第二天就指不到人。

## 四、在线状态 presence（待做）

现在房间只有一份「全房间在放什么」（`PartyNow`）。要做好友，得改成**每人一份**：

```ts
interface Presence {
  id: string          // 身份
  name: string
  nowPlaying: string  // 他在听什么
  nowArtist: string
  sources: string[]   // 他能取哪些平台的音源（决定他能不能听同一档）
  updatedAt: number   // 这份状态什么时候的
}
```

房间广播的负载从 `{ now, members: [{id,name,host}] }` 变成
`{ members: Presence[] }`——房主每 2 秒推一次，客人只读。

**过期规则**：本地记的 presence 超过 5 分钟没更新就算离线。这条比 socket 断开更可靠——
客人假死（进程卡住但连接还在）时，socket 不会告诉你，时间会。

## 五、好友（待做）

### 存什么

```ts
interface Friend {
  id: string      // 对方的身份
  name: string    // 加的时候他叫什么（改名不会自动同步——没有服务器）
  addedAt: number
}
```

存本机 `aurora.friends`。**单向**：我记你为好友，不代表你记我。这是没服务器的必然结果，
界面上要说清（比如按钮写「加入好友」，不写「加为好友」）。

### 在线怎么算

好友列表里每行：

```
● 张三        在听 南部Southside      [进他的房间]
○ 李四        3 天前一起听过          —
```

- **在线** = 本地 presence 表里有他，且 `updatedAt` 在 5 分钟内；
- **能进房间** = 记着上次见他时房间的地址与房间码。**这是猜**：他的端口可能变了。
  点进去失败就明说「他可能换地址了」，不要转圈。

### 怎么加

房间里成员列表，每人一颗「加入好友」。没有申请/同意那套流程——没有服务器，
双向握手要两边同时在线且互相看得见，做不完整就不做半套。

## 六、联网（已有，本次只补两处）

现在的房间协议：房主监听 → 客人 `hello` 验房间码 → 房主广播 → 转发可选。

要配合 presence 补两处：

1. **`hello` 带 `sources`**：客人自报能取哪些平台的音源，房主据此判断「他能不能直接听」。
   这决定转发要不要开——能自己取的就别让房主扛带宽。
2. **广播带每人的 presence**：见上。

## 七、界面（三处）

| 位置 | 加什么 |
|---|---|
| 一起听页 | 成员那一行，每人右边一颗「加入好友」 |
| 一起听页 | 一块「好友」：在线在上（带在听什么），离线在下 |
| 播放页房间带 | 成员名后面标「好友」，一眼看出谁是自己人 |

## 八、分期

| 期 | 内容 | 依赖 |
|---|---|---|
| P1 | 身份 uuid | — | ✅ 已完成 |
| P2 | presence：广播带每人状态、hello 带 sources | P1 | 待做 |
| P3 | 好友表 + 房间里加好友 + 好友块 | P2 | 待做 |
| P4 | 「进他的房间」（记住上次地址） | P3 | 待做 |

P2 是真正的分水岭：没有它，好友列表只能显示名字，显示不了「在听什么」——
那和通讯录没区别。

## 九、明确不做

- 不做账号体系（没有服务器，也没有必要）；
- 不做跨房邀请、跨房聊天（需要中继）；
- 不做好友申请与同意（同上）；
- 不把好友关系同步到云端（同上）。
