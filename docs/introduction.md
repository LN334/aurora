## 1. 它是什么：一个容器，不是一家曲库

Aurora 不带音乐内容。它把「你已经有账号的那几家」和「你本地的文件夹」摊平成同一个曲库：

- 同一首歌在四家都有的，只占一行，行上标出哪几家收了；
- 点播放时按你自己排的音源优先级，挑第一个**真能放**的；放不了就跳过并说明，不绕过付费；
- 首页是一堵会转的封面墙；「漫游」是一条放不完的推荐流，不告诉你还剩多少首；
- 窗口配色跟着当前封面走，界面本身不预设颜色。

三个明确的不做：

1. **不做曲库**。拿不到版权，也不假装拿得到；它永远是各平台的客户端。
2. **不破解付费**。会员曲只给「这首要会员」，不找破解源。
3. **不做第二套主题系统**。配色跟封面已经够，再叠皮肤会打架（见 `docs/ui-design.md` 的「明确不做」）。

## 2. 品牌故事

### 2.1 名字从哪来

Aurora 是极光。选它不是因为「极光很酷」，而是因为这个自然现象刚好对上产品的三件事：

- **它是多束光叠在一起的结果**，不是一束光的直线——对应四家平台加本机汇进同一个曲库；
- **它有范围、没有方向**，缓慢流动、慢慢散开——对应「漫游」：不给你一条歌单路线，只给你一片可听的区域；
- **它自己不发声**，只是把别处的光呈现出来——对应这个客户端：它是容器，不是内容源。

### 2.2 与「航天海报」的对照

设计过程中有一张参考海报（CZ-10 长征十号）：一根极细的光柱贯穿中轴、巨大的淡月牙、上下大片留白。真正学到的不是色值，而是三件事：

1. 敢只放一个东西；
2. 明暗的决定权只交给一个光点，其余由它推导；
3. **方向由叙事定，不由构图定**——同一套语言，光向外是航天，向内是 Aurora。

于是有了这句内部准则：

> **光不出发，光落下。**

航天是「一束光离开原点，去往远方」；Aurora 是「一束光落进容器，慢慢漾开」。所以图标里的光不能是射线、不能是向外冲的尾迹，只能是贴着结构向内舒展的一片。

### 2.3 字母 A：为什么没有横杠

品牌字形是等宽两笔的 A，**刻意去掉横杠**。三个原因：

- 在 20–21px 的标题栏尺寸，三笔 A 的横杠会糊成实心，读起来像三角形；两笔的「尖峰」更干净；
- 去掉横杠后，A 更像一个**开口的容器**——两条边把东西拢进来，而不是一个封闭的字母；
- 它和图标、托盘共用同一份 512 设计坐标（`scripts/make-icons.mjs`），保证三处不会各长一个样。

界面里用的 `BrandMark` 是**固定三色渐变**（`#2ad9c8 → #36aef3 → #8f5cf0`，青绿—天蓝—紫），不跟封面变色。理由写在组件头注释里：界面已经跟着封面变色，logo 再变就不是 logo 了。

### 2.4 应用图标的四次迭代

| 阶段 | 样子 | 为什么被换掉 |
| --- | --- | --- |
| 最初 | 蓝紫渐变方块 + 白色实心 A | 用户原话「还是丑」，且和界面里的两笔 A 不是同一个东西 |
| 二版（用户自选） | 深蓝底 + 极光绿蓝紫缠绕的立体 A，强发光 | 缩到 48px 轮廓被光吞掉，32px 成色团；绿占 60%，违背三色比 |
| 三版（当前） | 深灰蓝圆角底 + **白色半透明玻璃质感的 A**，右下腹漏出一道很淡的彩虹光 | 这是定稿：玻璃是容器，虹光是漾开的光 |
| 小尺寸 | 16/24/32 单独提对比度、压掉虹光 | 直接缩会在 24px 起糊，横杠与腿粘连 |

当前图标：七档（16/24/32/48/64/128/256）打进 `build/icon.ico`，四角透明（0.7.3 每边再裁一像素，去掉半透明高光造成的白边）。设置里还能换图标：给一张方图，程序自己裁方、切圆角、出七档与 ICO（0.7.2）。

### 2.5 故事如何落到功能上

- **多源汇聚** → 同曲一行、平台徽章、按音源顺序取流；
- **漫游无终点** → 不显示总数，切一首补一首；去听歌单自动退出并还原循环模式；
- **容器不发声** → 播放器只是播放器：不建曲库、不猜你口味、不伪造推荐理由；
- **光随封面** → `--accent` 从当前封面取色，整个界面的强调色由它派生；没有播放时是钢灰。

## 3. 品牌风格

### 3.1 一句话气质

**冷静的深空灰蓝 + 一层会呼吸的玻璃 + 一点从封面借来的颜色。** 不放霓虹、不做发射、不堆装饰；克制到接近工具，但仍然有温度。

### 3.2 图形语言

| 元素 | 规格 |
| --- | --- |
| 字母 A | 等宽两笔、无横杠、尖角；端点圆角 |
| 品牌渐变 | `#2ad9c8` 青绿 40% / `#36aef3` 天蓝 35% / `#8f5cf0` 灰紫 25%（界面 BrandMark 固定用） |
| 图标底 | 深灰蓝圆角方块（哑光深空底，边缘只有一层极淡的玻璃高光），四角透明 |
| 虹光 | 只在 A 的右下腹，极淡，绿→青→蓝→紫，像从缝里漏出来 |
| 小尺寸策略 | 16–32px 提对比、压虹光，保 A 的轮廓 |

### 3.3 界面：一层玻璃，不是一堆卡片

0.7.7 重做后的底子只有一句话：**整窗口一块玻璃，卡片是玻璃上的薄片，壁纸透出来。**

- 深色 `--wp-glass: 0.56`，浅色 `0.66`（浅色要更实，否则亮壁纸会把字吃掉）；
- 玻璃三件套固定：半透明底 + `backdrop-filter: blur()` + 1px 内描边。缺描边时，深色壁纸上的卡片会「浮」起来找不着边；
- 内容层不再各自垫底：只有「整块的面」（每日推荐、上次听到、快捷卡、面板）才铺底；封面式卡片（歌单卡、专辑卡、最近听过）靠封面自己分块——0.7.8 / 0.7.9 就是在修这条边界的两次越界；
- 播放条浮在内容之上（圆角 + 投影），不占布局最后一行——否则两块底的交界处永远有一条线。

### 3.4 颜色与文字

- **唯一动态值是 `--accent`**：从当前封面取主色，写进 `--accent-rgb`；所有强调色从它派生。没有任何组件写死品牌色；
- **灰阶只有一条**：深色 `--ink-1000..500` 从深到浅，浅色整条翻过来，角色不变；
- **文字只有三档**：`--text-hi / mid / low`，深浅各一套，别处不再单独提亮；
- 三条文字档 + 一条灰阶 + 一层玻璃，就是全部。换主题、开关壁纸都不需要动组件规则。

### 3.5 尺度

| 区块 | 形态 | 关键尺寸 |
| --- | --- | --- |
| 今天听什么 | 左列文字 + 右侧可转封面墙 | 墙 660×220，卡 128px，九张同屏 |
| 推荐歌单 | 六列方卡封面墙 | `repeat(6, minmax(0,1fr))`，窄屏 4 列 |
| 推荐专辑 | 一行横条，可左右翻 | 一屏 5 张 |
| 最近新歌 | 左主推 + 右九行一屏 | 主推 320 方图，列表最大高 378px，行高 42px |
| 最近听过 | 八张窄卡 | 八列 145px，副标相对时间 |
| 设置 | 单页玻璃板 | `max-width: 820px` 居中 |

间距令牌：4 / 8 / 12 / 16 / 24 / 32 / 48；圆角：控件 6、面板 10、封面 12。字号：display 27 / title 15 / body 13.5 / meta 12 / micro 11。

封面墙为什么是九张：再多封面里的字就看不清，再少转不动；九张时相邻两张交叠约 55–63px，压住边缘又留出可辨的侧边。

### 3.6 动效：三条铁律

1. **任何输入只改目标，不改位置。** 滚轮、键盘、点侧卡都只写「目标位置」，位置由帧循环逼近。直接改位置会让事件间隔不均变成可见的抽搐。
2. **帧循环里不 setState。** 每帧重渲染会让九张卡一起 diff，抖。位置、透明度、z 序直写 `el.style`，只有「中心换到另一张」才让 React 重渲染一次。
3. **吸附用弹簧，不用线性插值。** 线性插值没有回弹；落位段用欠阻尼弹簧（`acc = gap * 190 - vel * 14`，ζ≈0.51），冲过去再弹回来。

还有两条别做：不要给帧循环驱动的元素加 CSS `transition: transform`（每帧重启动，永远追不上指针）；不要给每帧重绘的容器加 `mask-image` 或 `backdrop-filter`（整块每帧重新合成）。

### 3.7 文案

- 说人话，不说机制；错误写「怎么办」，不写异常名；
- 一句话只做一件事；设置项说明写「关掉会怎样」；
- 首页不解释推荐从哪来（曾加过「四家平台交叉推荐的 30 首」，被明确否掉）；
- 首次引导只放能点的东西，一行一个开关，最多两页。

### 3.8 七条界面硬规则

写在 `docs/ui-design.md`，改界面前必须遵守：

1. 一页只有一个标题（外壳打印，页内不打）；
2. 没有页内侧栏（导航只在左栏一处）；
3. 本地与在线共用同一套卡片与列表，来源只用徽章区分；
4. 颜色只来自封面，不在组件里写死；
5. 四个平台一起改，不许只改一家；
6. 交互不能走进死路（关掉功能要留说明或回入口）；
7. 不用系统弹窗（`confirm`/`alert` 一律换成应用自己的 Modal）。

## 4. 产品全貌

### 4.1 导航

- 顶部「现在 / 漫游」；
- 我：「我喜欢的 / 最近播放」；
- 库：「歌单 / 专辑 / 艺人 / 本机」——同一组，不拆两个分区；
- 底部「设置 / 账号 / 收起侧栏」；
- 平台不单独占一级；搜索只有顶部一个入口（`Ctrl K`），因为搜索是动作不是目的地。

### 4.2 首页信息架构

顺序：问候 → **今天听什么** → 上次听到 → 四张快捷卡 → 推荐歌单 → 推荐专辑 → 最近新歌 → 最近听过。

排法按「手上想干什么」优先于「有什么可以看」：每日推荐是唯一「现在就能放」的动作，放最上；「接着听」第二；快捷卡是导航，排在两个播放动作之后；再往下才是需要翻的发现区。

### 4.3 漫游

原生客户端的流式模型：四家各拉一批、首家先开播（约 0.5 秒出声），切一首补一首；不报总数、不装成歌单（队列面板叫「漫游 · 接下来」）；有「不再推」「结束漫游」；去听歌单或专辑自动退出并还原循环模式；未登录时用对话框说「漫游需要登录」。

### 4.4 我的与编辑

- 我喜欢：四平台红心合并成一条，页头按平台计数，每行标出可放平台；写回时在平台上做一样的事；
- 歌单：按平台分组，可新建/改名/删/拖拽排序/`Alt+方向键`/m3u 与 m3u8 导入导出；
- 本机：歌曲/专辑/艺术家/文件夹，扫描 14 种格式。

### 4.5 播放与歌词

四档播放模式（顺序 / 列表循环 / 单曲循环 / 随机）合成一颗键；10 段 EQ 5 预设、双击归零；交叉淡化真按秒生效；ReplayGain + 限幅；队列面板；启动可恢复上次队列（只摆着，不自动开唱）。

全屏歌词：当前句放大、上下渐隐、原文与译文分两行；可滚轮/拖动，停手 4 秒回到正在唱的那句；无词时给「从公共歌词库找一次」并写明会上传歌名与艺术家。舞台页是另一套九槽连续滚动 + 粒子。

桌面歌词是独立无边框透明置顶窗口：静止只有文字与径向暗晕，鼠标浮出胶囊工具条（上一句/播/下一句/锁/关）；锁定时鼠标穿透，但仍可悬停拖动点击。

### 4.6 系统集成

托盘（关窗不退出）、任务栏缩略图按钮、SMTC 与硬件媒体键、媒体卡片带封面；全局快捷键 空格 / ←→ 5s / Ctrl+←→ 切歌 / ↑↓ 音量 / L / E / Ctrl+K / F11 / Esc / Ctrl+Alt+L / Ctrl+Alt+K。

### 4.7 背景

可接 Wallpaper Engine（Steam 版）：场景 `.pkg` 由内置 WebGL 引擎渲染，也支持视频/网页/图片；只读不启动；跟随当前壁纸或钉死；画质省电 20 / 均衡 30 / 清晰 60 帧。

## 5. 技术架构

### 5.0 工程数据口径（可复现）

本节和全文的代码体量、行数、质量数字都指同一个快照：

- **测量时间**：2026-11-12；**提交** `071b652`（`chore(release): 0.7.9`）。
- **范围**：只算 `git ls-files` 已跟踪的文件；不含 `node_modules`、`dist*`、`release*`、`vendor/`、`.probe-*` 与本地探针产物。
- **两种行数口径**：
  - **总行** = 文件里 `\n` 的个数（末尾没有换行时补 1），等同 `wc -l`；
  - **非空行** = 按 `\r?\n` 切开后 `trim()` 非空的条数。编辑器状态栏与 PowerShell `Get-Content | Measure-Object -Line` 给的是非空行。

复现命令（仓库根，Node 20+）：

```bash
git ls-files | node -e '
const fs=require("fs"),cp=require("child_process");
const files=cp.execSync("git ls-files").toString().split("\n")
  .filter(f=>/\.(ts|tsx|mjs|cjs|js)$/.test(f));
let L=0,N=0;
for(const f of files){const t=fs.readFileSync(f,"utf8");
  const nl=(t.match(/\n/g)||[]).length;
  L+=t.endsWith("\n")?nl:nl+1;
  N+=t.split(/\r?\n/).filter(l=>l.trim()).length;}
console.log(files.length,L,N);'
```

### 5.1 进程与页面

- 主进程 `electron/main.ts`（872 行 / 814 非空行）+ 拆出的 `electron/ipc/`（11 个文件：app / library / wallpaper / overlay / updates / lyrics / player / settings / downloads / maintenance + host.ts 声明依赖）；
- 渲染层两页：`index.html` 播放器 + `overlay.html` 桌面歌词（各自一套入口，不互相路由）；
- 四个私有协议，全部由主进程供给：
  - `aurora-app://app/` —— 生产渲染页（CSP 只放行私有协议）；
  - `aurora-media://` —— 本地媒体与封面缩略图；
  - `aurora-remote://` —— 在线音频/封面代理（Range 206、CORS、地址白名单、拒本机/内网）；
  - `aurora-wallpaper://` —— Wallpaper Engine 工程文件（拒绝越界、支持 Range）。

为什么必须有 `aurora-remote`：生产页 CSP 不允许外部源，而播放走 Web Audio——对一个页面无权读取的源，Web Audio 输出的是**静音**而非报错。代理同时解决 CORS 与 Range，`stream: true` 让拖动有效，`corsEnabled` 让 `crossOrigin=anonymous` 成立。

### 5.3 平台适配层

- 注册表 `Map<ProviderId, Provider>`，UI 只调 `listProviders()`；`providerForTrack(track)` 反查；
- 契约是 **capabilities 布尔**（search / playback / lyrics / auth / collections / write 等），不是「有没有这个函数」；写不动的功能据此置灰并直说，而不是点了没反应；
- 歌曲自带 `{ kind: 'online', providerId }`；侧栏与搜索页从注册表生成；
- 可用性三态：`playable` / `unknown + restricted` / `takenDown`，判决只来自真实请求且不回写；
- 平台专属登录窗留在各自目录，不进公共层。

音源侧是另一条接缝：`src/features/library/source.ts` 的 `TrackSource` 七个成员 `id / name / summary / online / streamUrl(track) / artUrl(track) / lyrics(track)`。新增一家平台要同时过两道契约：账号侧 Provider 与音源侧 TrackSource。

### 5.4 播放链路与三条不变量

链路：`pickPlayable(track)` → 逐版本问各平台取流 → `engine.load(track, autoplay)` → `driver`（合成驱动或真实 audio）→ Web Audio（EQ/增益/淡化/分析）→ `MediaSession` / SMTC。

三条不变量都是踩过坑写死的：

1. **取流不重入**。两路同时取流会抢同一个 audio 元素，抛 `AbortError` 后进度永远 0:00。现在先问 `driver.isTrackReady(track)`，就绪就不再重载；`engine.play()` 的 catch 首行遇到 `AbortError` 直接返回，不把按钮按死。
2. **没源就跳，不钉住**。`engineHooks.unplayable(track)` 把决定权交给 actions；连跳上限 6 首后停下并给可见提示。引擎只如实报告，不知道「连跳几首了」。
3. **恢复的队列不自动播**。恢复只是摆着；没有指上音频元素时点播放先装载再播。

播放历史只存本机：按本地日历日累计、最近 60 条、3 分钟内重复不算两条；`recordProgress` 只在 currentTime 前进且增量 ≤3 秒时计入（seek 不算）。

### 5.5 歌词链路

取词三级：本版本平台 → `track.versions` 里其它平台（词与谁出声无关）→ LRCLIB（在线歌词默认关，打开时才发歌名/艺术家/时长）。

渲染两条路：

- 播放页 `LyricRoll`：一条长列表 + 帧循环写 transform，滚轮/拖动只改目标，停手 4 秒回 active 行；行高 = 字号 × 2.588，改字号必须同步改行高；
- 舞台 `LyricColumn`：9 个固定槽，整列连续滚动，槽高用 `offsetHeight` 量（不能用 `getBoundingClientRect().height`，那带 `scale()`）；每帧直写 `--far` 与 class，不 setState。

译文拆分判据在 `src/features/lyrics/line-parts.ts` 的 `splitLyricLine`：含「 / 」且前半段无中日韩字符才算译文，合作署名不拆。

### 5.6 首页数据链路

- `loadPlatformDaily()` 用 `Promise.all` 同时问所有声明了 `recommendations.dailySongs` 的平台，各家失败返回空不影响整块；`interleaveBySource` 按来源轮流取，保证第一屏四家都有；不足 30 由本机按口味补；
- 批次按 `DAILY_RESET_HOUR = 6`（早六点换批，凌晨算前一天）；平台那份用 `rotateBySeed(daySeed + provider.id)` 按日挪起点；
- 推荐歌单/专辑/新歌共用同一个「推流来源」勾选（关掉一家=别拿它推给我），缓存按平台集合分键、TTL 10 分钟；未登录平台用 `GIVE_UP_MS = 1800` 放弃等待；
- 「等齐再画」用 ready 布尔 + 短兜底窗，不先画一批再换源。

### 5.7 漫游模型

快池 first-win：四家并发，第一家带回歌就先开播，其余回来补进队列；后台 `fillRoamPool()` 补整池；`commitRoam()` 把过滤名单、清滚动记录、setState、`parkRepeat`、`playQueue` 收成一处；`refillIfLow` 在队列低位时补批，按量截断，开趟不叠两批。

### 5.8 壁纸链路

主进程从注册表 `SteamPath` / 两个 HKLM `InstallPath` / `libraryfolders.vdf` 找 Steam 根，用 `wallpaper_engine/config.json` 判定，扫 `workshop/content/431960` 与引擎 `projects`；只取 `selectedwallpapers`（不读 recent），缓存 30 秒，全程只读。渲染层 `Backdrop.tsx` 对场景动态 `import('webwallgl')`（约 1.1 MB，被 manualChunks 排除出共享 vendor）；进出舞台共用窗口层那一份背景，不再重建（0.7.4 把退舞台最长帧间隔从 1467ms 降到 13ms）。

### 5.9 更新链路

手动与自动是两条路：手动「检查 → 下载 → 安装」每步都要按；自动默认开，后台查、后台下、没在放歌时自己换上（0.7.5 起静默 NSIS，0.7.6 起一键安装器不弹向导）。安装收尾会补桌面/开始菜单快捷方式（0.7.8）。`latest.yml` 是 electron-updater 唯一读的清单，漏了自动更新就断。

### 5.10 状态与持久化

- 渲染层状态用 Zustand；设置项每项一个真源（主进程 `settings/store.ts`、纯渲染 `motion.ts`、`wallpaper/store.ts`）；
- 凭据用 DPAPI 加密只存本机；多档案隔离（`aurora.player.prefs::<档案 id>` 这类键）；
- 主题/玻璃/歌词字号/行密度等写 localStorage；桌面歌词位置、窗口行为由主进程兑现；
- 巡检与测试一律用独立 `--user-data-dir`，不碰真实账号。

### 5.11 质量体系

`npm run check` = 类型检查 + 499 个单元测试 + 四项静态审计（2026-11-12 实测）：

| 审计 | 拦什么 |
| --- | --- |
| reachability | 入口 56、可达 326 源文件；孤立文件（写了没人 import） |
| css | 776 个 class；死选择器必须为 0 |
| stale-paths | 指向已不存在文件的路径引用 |

`npm run smoke` 起真窗口逐页 13 屏：收控制台错误/破图/未捕获异常，联网搜一次并点开在线歌确认播放条走过 0:00，有 Wallpaper Engine 时选壁纸连拍两帧确认在动。CI 在 **windows-latest** 跑 check + build（单元测试断言 Windows 路径语义，ubuntu 会假红）；CI 不打包——安装包要带 `vendor/KuGouMusicApi`，而 vendor 不入库。

## 7. 已知边界

- 四家平台全是非官方逆向接口，随时可能失效；失效时修「同一家的另一条官方路径」，不换平台、不静默失败；
- 不破解付费：会员曲只显示「要会员」，未登录平台只推公开榜；
- 安装包未签名，首次运行可能被 SmartScreen 拦；
- 只有 Windows；界面只有中文；动态背景只支持 Windows + Steam 版 Wallpaper Engine；
- 手机端尚未支持：390×844 实测左栏 224px、内容区 166px、86 个可点元素里 80 个 <40px。三条路（局域网遥控器 / 加安卓壳 / 独立 App）已评估，推荐先做遥控器；
- 音质、外观、快捷键是设备级设置，不跟账号档案走；
- 关于页措辞：试验性作品，功能与界面可能随时改动，不要用于重要数据。

## 10. 给接手的人

按这个顺序读，两个小时能上手：

1. `README.md` 的「定位」「功能」「开发者」三节；
2. `docs/ui-design.md` 七条硬规则 + 尺度表；
3. `docs/architecture.md` 的分层、平台层、播放与歌词链路；
4. `src/features/player/engine.ts` 与 `actions.ts`（播放的三条不变量都在这）；
5. `src/styles/tokens.css`（只有一条灰阶、一层玻璃、三档文字）；
6. 跑一次 `npm run check`，再跑一次 `npm run smoke`。

改任何界面之前先问三个问题：这个颜色是不是该从封面来？这四条平台链接是不是都会一起变？关掉这项功能的人能不能找到回来的路？

改任何播放相关代码之前先看 `engineHooks` 与 `isTrackReady`：**不要用重试解决竞态**，消除重入才是治本。
