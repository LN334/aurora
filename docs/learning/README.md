# 从零读 Aurora

这是一份**学习资料库**，不是项目文档。

项目文档（[docs/introduction.md](../introduction.md)、[docs/architecture.md](../architecture.md)）回答「这软件是怎么分工的」，是给人查的。
这套东西回答的是另一个问题：**一个还没写过代码的人，怎么从零走到能在这个仓库里动手改东西。**

---

## 先说清楚你面对的是什么

| 事实 | 数字 |
| --- | --- |
| 项目代码 | 约 9.2 万行 TypeScript / TSX / CSS（不含依赖） |
| 主进程 | 115 个文件，约 3 万行 |
| 渲染层业务逻辑 | 144 个文件，约 2.2 万行 |
| 页面 | 61 个文件，约 1.4 万行 |
| 样式 | 19 个文件，约 1.6 万行 |
| 测试 | 104 个文件，约 1 万行，全部可裸 Node 跑 |
| 提交历史 | 682 个提交，2026-10-14 至今 |

这不是一个「教学项目」。它是一台真的在跑的桌面应用，有四个在线音乐平台、私有协议、壁纸引擎、自动更新、打包发版。

所以这份资料不假装「读完就能全懂」。它做的是相反的事：**把一座 9 万行的山，切成六段能爬的坡，每一段都告诉你踩在哪块石头上。**

## 六站路线

每一站都有「只学这些」（别贪）和「验收」（做到才算过）。

| 站 | 主题 | 只学这些 | 验收标准 |
| --- | --- | --- | --- |
| **0** | 起步 | 终端六条命令、npm 三条、git 三条 | 能 `npm run dev` 开出窗口；能单独跑一条测试 |
| **1** | 语言 | 值、变量、函数、数组与对象、闭包、`async/await`、TypeScript 类型 | 能逐行讲清 `src/features/player/crossfade.ts`，并给它加第 5 条测试 |
| **2** | 界面 | 盒模型、flex、CSS 变量；React 组件、props、state、三个常用 hook | 能在一屏内改文案与配色，且不破版式 |
| **3** | 桌面 | Node 的文件与模块；Electron 三进程、IPC、preload、私有协议 | 能画出一条「页面点一下 → 磁盘上读一个文件」的完整链路 |
| **4** | 状态与数据（贯穿站） | 类型设计、zustand、provider 注册表、持久化 | 能说清「点播放」经过的 6 个文件，以及为什么这么拆 |
| **5** | 工程化 | `node --test`、双 tsconfig、Vite、四项审计、打包 | 能跑 `npm run check`，红了能指出红在哪一项、为什么 |

顺序不是随便排的：**1 到 5 是依赖关系**。看不懂 `async` 就读不懂 IPC；读不懂 IPC 就读不懂 preload；读不懂 preload 就只能背架构图。

**两处编号说明**（第一次看容易糊涂）：

- **站号从 0 开始，文件号从 01 开始**，所以站 1「语言」对应 `02-语言…`，站 2「界面」对应 `03-…`，依次错开一位。第 0 站「起步」就是 `01-起步…`。
- **第 4 站没有独立章节**。状态与数据不是一门能单独教的课，它散在 `02`（类型）、`03`（state 与 hooks）、`06`（store 与接缝）里，验收也在第 6 章读码路线里完成。这是刻意的：**状态设计离开真实业务就变成空谈。**

## 三种读法

### 全程读（推荐，零基础）

`01 → 02 → 03 → 04 → 05 → 06 → 07`，配 `08` 当字典。
每天 1–2 小时，**三到六个月**能到「独立改一个小功能」的水平。这是诚实的估计，不是吓你：语言两三个月，界面一两个月，桌面和工程化各一个月，再加上你必然会走弯路的时间。
`文献/` 里的五篇专题长文按需插入，别当任务——**它们是「我想知道得更深」时去的地方，不是必读清单。**

### 最短路径（只想赶紧改点东西）

`01 → 06 → 07`。跳过语言课，靠第 6 章的「读码路线」硬啃，遇到不懂的语法回 `02` 查。这条路能让你**一周内改出第一个改动**，但会在第三周开始还债——基础不牢，看什么都像天书。

### 查字典

`08` 是术语表 + 文件地图 + 常见错误对照。任何时候卡住，先查它。

## 四条学习法（比章节内容重要）

**一、一次只读一个文件。**
这个仓库有一批「为了能被测试钉住而单独拆出来」的小文件，12 行、15 行、20 行，正好当课文。它们不是玩具代码，是生产代码——只是被刻意拆到最小。
从 `electron/pure/invite-arg.ts`（12 行）和 `src/features/player/crossfade.ts`（15 行）开始，别从 `main.ts`（1000+ 行）开始。

**二、不许只读不跑。**
读代码产生的「我懂了」是幻觉。改一个数字、跑一次、看结果变了，才是真的懂。第 7 章 30 道练习全按这个逻辑设计。

**三、遇到「为什么这么拆」，先看注释。**
这个仓库的注释密度罕见地高，而且写的是**决策理由**，不是「这里给变量赋值」。举一个真实的例子：

```ts
// src/features/player/crossfade.ts:1-7
/**
 * 切歌时淡出／淡入各用多久（毫秒）。
 *
 * 这段算法单独拿出来，是为了让它能被测试钉住：上一版在引擎里读 `crossfadeSec`
 * 只把它当成一个开关（>0 就淡 190ms），滑到 12 秒和滑到 1 秒没有区别。
 */
```

七行注释讲完了「为什么有这个文件」。这种注释在仓库里有几千条，等于一位随叫随到的老师。

**四、只学到「够读下一段代码」为止。**
不要为了学 Electron 去把 Node 官方文档读完。这份资料每一站都写了「只学这些」和「这里不用学」，后者同样是内容。**学不完是常态，学错顺序才是问题。**

## 项目地图（一句话版）

先建立方位感，再进第 0 站。

```
D:\Aurora
├── electron/            主进程：能碰文件、开窗口、联网的那一侧
│   ├── pure/            不碰 Electron 的纯函数 —— 为测试而拆的零件
│   ├── ipc/             页面能喊的每一句命令，一个文件一类
│   ├── protocols/       aurora-media: 这类私有地址的「服务器」
│   ├── netease/ qq/ kugou/ qishui/   四家平台的适配器
│   ├── main.ts          启动顺序（最长的一个文件，别从它开始）
│   └── preload.ts       唯一的桥：页面只能通过它跟主进程说话
├── src/                 渲染层：你看见的界面
│   ├── app/             外壳：标题栏、侧栏、路由、快捷键
│   ├── views/           一页一个文件（HomePage、NowPlayingPage…）
│   ├── features/        业务逻辑：播放、歌单、在线平台、设置、下载…
│   ├── ui/              通用零件：骨架、提示、图标、格式化
│   ├── styles/          tokens.css 定令牌，其余按页分文件
│   ├── App.tsx          组件树的总装厂
│   └── main.tsx         React 的入口，也负责一堆「启动时先做一次」的事
├── tests/               104 个纯逻辑测试，node --test 直接跑，不用 Electron
├── scripts/             构建、审计、性能探针（纯 .mjs，很适合当 Node 教材）
├── docs/                项目自己的文档（查，不背）
└── package.json         所有命令的出处，先看 scripts 段
```

依赖方向是硬规则：**`views → features → ui`**，主进程的 `electron/pure` 里不许 import Electron（不然裸 Node 测试加载不了）。这条规则会在第 5、6 章反复出现。

## 每一站的教学格式

统一五段，方便你跳读：

1. **要解决什么问题** —— 这一站补的是哪种能力
2. **最小知识** —— 讲得够用即止，配项目里的真实代码
3. **项目锚点** —— 去哪几个文件看，看什么
4. **自测** —— 能答上来才算过（答案不在文里，在代码里）
5. **练手** —— 一道 20 分钟能做完的事

这个仓库是别人的作品，你读它是为了学。
