## 一、术语表

按主题分组。每条：一句话 + 在本项目里的锚点。

### 1 · 运行时（程序跑在哪）

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **运行时**（runtime） | 让代码跑起来的那个环境。浏览器是一个，Node 是另一个 | 渲染层跑在 Chromium 里，主进程跑在 Node 里，同一个应用两种运行时 |
| **V8** | Chrome 的 JS 引擎，Node 也用同一个 | 不用管它，知道它是「把 JS 变成机器码的那层」就够 |
| **Node** | 能在服务器/桌面跑 JS 的运行时，**没有 DOM** | `electron/` 下所有文件 |
| **Chromium** | 浏览器内核。Electron = Chromium + Node + 一层胶水 | 渲染进程 |
| **主进程 / 渲染进程** | 前者管窗口和系统，后者管界面 | `electron/main.ts` vs `src/` |
| **preload** | 渲染进程启动前加载的脚本，唯一能碰 Node 又贴着页面的位置 | `electron/preload.ts` |
| **ESM / CJS** | 两种模块格式。`import` 是 ESM，`require` 是 CJS | 项目主体是 ESM；不设 `"type": "module"` 是为了跟 Electron 主进程兼容 |
| **DOM** | 页面在内存里的那棵树 | 所有 React 代码最终都操作它 |

### 2 · 模块与依赖

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **依赖**（dependency） | 别人写好的包，你装回来用 | `package.json` 的 `dependencies` |
| **devDependency** | 只在开发/构建时需要，不随应用发出去 | `typescript`、`vite`、`electron-builder` |
| **lockfile** | 锁死每个包的确切版本 | `package-lock.json` / `pnpm-lock.yaml` |
| **打包**（bundle） | 把一堆模块合成少数几个文件，浏览器才不用发几百个请求 | Vite 的 `build` |
| **tree-shaking** | 打包时删掉没用到的代码 | 决定了「没用到的代码到底会不会进产物」 |
| **有副作用 / 无副作用** | import 一个模块除了拿到导出，还干了别的事没有 | `src/main.tsx` 里那几行「只 import 不用」就是有副作用 |
| **循环依赖** | A 依赖 B，B 又依赖 A，运行到一半变量还是 `undefined` | 为什么规定 `features` 不许 import `views` |
| **裸导入** | `import x from 'react'`，不带路径的那种 | 走 `node_modules` 或别名解析 |

### 3 · 语言

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **类型注解** | 给编译器看的说明，跑起来会被抹掉 | `function f(n: number): string` |
| **类型推断** | 你不写，编译器自己猜出来 | 优先靠它，少写废话注解 |
| **联合类型** | 「这几个之一」 | `phase: 'walking' \| 'reading' \| 'done'` |
| **可选属性** | 可能有、可能没有的字段，读的时候是 `T \| undefined` | `Track` 里所有带 `?` 的字段 |
| **严格模式**（strict） | 把所有「可能是 undefined」的地方都变成编译错误 | `tsconfig.json` 的 `strict` |
| **窄化**（narrowing） | 用 `if` 判断后，类型自动收窄 | `if (!x) return` 之后，下面 x 就不是 undefined 了 |
| **泛型** | 类型也能当参数传 | `Map<K, V>`、`Promise<T>` |
| **可选链** | `a?.b` —— a 是空的就整体返回 undefined | 处理不完整的 Track |
| **空值合并** | `a ?? b` —— 只在 a 是 null/undefined 时取 b | 跟 `\|\|` 的差别：`0` 和 `''` 不会被当成空 |
| **闭包** | 函数记住了它出生时的外部变量 | 订阅函数、`setOnlineStreamLoader` 的回调 |
| **纯函数** | 同样输入永远同样输出，不改外部状态 | `electron/pure/` 下的一切 |
| **副作用** | 改文件、发请求、改全局变量 | 纯函数的反面；副作用要集中管理 |
| **解构** | `const { a, b } = obj` | 到处都是 |
| **卫语句**（guard） | 不满足条件就提前 `return`，避免层层嵌套 | 项目代码的主流写法 |
| **冻结的字面量**（`as const`） | 让常量保留字面量类型 | 常量表 |
| **类型断言**（`as`） | 「我保证它是这个类型」，编译器不再检查 | **少用**。能不用就不用 |

### 4 · 界面

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **组件** | 一个返回界面的函数 | `src/ui/` 里全是 |
| **props** | 父组件传给子组件的参数，只读 | `EmptyState({title, hint})` |
| **state** | 组件自己的、会变的数据 | `useState` |
| **受控组件** | 值由外面给，改动也由外面处理 | 输入框的 `value + onChange` |
| **key** | 列表里每一项的身份标识 | 用了 index 当 key 就会出现「删除后串位」 |
| **渲染** | 把数据变成界面 | 状态变 → 重新渲染 |
| **重渲染** | 组件函数被再次调用（不等于 DOM 变化） | 性能问题的第一嫌疑 |
| **memo / useMemo** | 跳过不必要的重算 | 别提前优化，先保证对 |
| **hook** | 以 `use` 开头的函数，能挂进 React 的生命周期 | `useSyncExternalStore` |
| **副作用钩子**（`useEffect`） | 渲染后执行，用于订阅/请求/定时器 | 记得写清理函数（返回值） |
| **CSS 变量** | `--accent: #7d8899`，一处定义处处使用 | `src/styles/tokens.css` |
| **设计令牌**（token） | 把颜色/间距/字号起名成变量 | 同上，项目的视觉规则都在这 |
| **盒模型** | 内容 + padding + border + margin 四层 | 尺寸对不上时第一个要想到的东西 |
| **flex** | 一维布局 | 大部分行/栏 |
| **grid** | 二维布局 | 卡片墙 |
| **CSP** | 内容安全策略，白名单决定页面能加载什么 | `index.html`；加私有协议必须改这里 |
| **骨架屏** | 数据没来之前画的假结构，防止跳动 | `src/ui/Skeleton.tsx` |

### 5 · 状态与数据

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **store** | 一份全局状态 + 改它的方法 | zustand |
| **订阅** | 「这个值变了通知我」 | `subscribe` |
| **选择器** | 只取你要的那一小块，避免无关变化也重渲染 | `useStore(s => s.x)` |
| **持久化**（persist） | 把状态写进 localStorage/磁盘，下次还在 | `src/features/player/store.ts` |
| **序列化** | 对象 → 字符串/字节 | JSON.stringify |
| **索引**（index） | 提前算好、存起来的数据，用空间换时间 | 本地曲库索引（主进程持有） |
| **缓存** | 算过一次就留着 | `aurora-cache:` 协议 |
| **增量更新** | 只处理变化的部分 | 扫描靠 `size + mtimeMs` 判断文件有没有变 |
| **乐观更新** | 先改界面，再发请求，失败再回滚 | 收藏这类操作常用 |
| **单一数据源** | 同一份数据只有一个权威位置 | 索引在主进程，store 只是镜像 |

### 6 · 音频

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **Web Audio** | 浏览器的音频处理图 | `src/features/player/engine.ts` |
| **AudioContext** | 音频图的入口对象 | 一个应用通常只要一个 |

### 7 · 跨进程

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |

| **CORS** | 服务器允许跨源访问的声明 | 协议 handler 返回的响应头 |

### 9 · 发版

| 词 | 一句话 | 本项目锚点 |
| --- | --- | --- |
| **版本号** | `主.次.修` 三段 | `package.json` 的 `version` |
| **tag** | 给某个提交起个名字，通常是版本号 | `git tag v0.9.26` |
| **Release** | 附着在 tag 上的发布页，能挂文件 | GitHub Releases |

## 二、常见错误对照

排错顺序：**先读错误原文 → 再定位自己最后改的那个文件 → 最后才怀疑环境**。

| 你看到的 | 人话 | 怎么办 |
| --- | --- | --- |
| `Cannot find module 'electron'` | 在纯 Node 里跑了主进程代码 | 主进程代码只能在 Electron 里跑，测试要测 `electron/pure/` 里的纯逻辑 |
| `require is not defined` / `import` 报错 | 模块格式用错了 | 看文件的扩展名和 `tsconfig` 的 `module` 设置 |
| `Reparsing as ES module: ... WARNING` | 裸 Node 把 TS 当 ESM 重新解析了一次 | **正常现象**，不影响测试结果 |
| `TS18048: 'x' is possibly 'undefined'` | 你没确认 x 存在就用它了 | 加卫语句；或 `if (!x) return` |
| `TS2345: Argument of type ... is not assignable` | 传的参数类型不对 | 看函数签名，别用 `as` 糊过去 |
| `TS2339: Property 'x' does not exist on type` | 你以为有这个字段，其实没有 | 先 `console.log` 看真实对象 |
| `window.aurora is undefined` | preload 没跑，或 API 没暴露，或类型没声明 | 三处对齐：preload 暴露 / `env.d.ts` 声明 / 调用处 |
| `Refused to load ... because it violates CSP` | 资源被内容安全策略拦了 | 去 `index.html` 的 `-src` 白名单里加 |
| 点了按钮没反应，控制台也没报错 | 事件没绑上，或绑了但 handler 早退 | 在 handler 第一行 `console.log`，确认它真的进了 |
| 列表明明改了数据但界面不变 | 直接改了对象/数组，没换引用 | 用新对象替换旧的（不可变更新） |
| 应用启动就崩，退出码 `0x80000003` | 打包产物被安全策略拦了（本机特有：`D:\Aurora` 被挂了 AppContainer ACL） | 把产物复制到 `%TEMP%` 或 `%LOCALAPPDATA%` 再跑 |
| Electron 起不来，`app.whenReady()` 永远不返回 | 环境变量 `ELECTRON_RUN_AS_NODE=1` 把 Electron 当成了纯 Node | 清掉这个变量（`Remove-Item Env:ELECTRON_RUN_AS_NODE`） |
| `npm install` 卡住 / 连不上 | 本机访问 registry 会被重置 | 用 `--registry=https://registry.npmmirror.com` |
| git push 卡在 `could not read Username` | 没配凭据助手 | 走代理 + 指定 `credential.helper`（看第 1 站） |
| 改了主进程代码没生效 | 主进程不热更新 | 重跑 `npm run dev` |
| 改了 preload 没生效 | 同上，而且渲染进程要重新加载 | 重跑 dev，或关掉窗口重开 |
| 打包很慢/失败了但看不出原因 | 依赖要从网上重新下 | 看 `npm run dist` 的完整输出，别只看最后一行 |

## 三、命令速查

```bash
# 开发
npm run dev              # 编译主进程 + 起 Vite + 起 Electron，带热更新
npm run build            # 生产构建（不打包安装器）
npm run typecheck        # 只查类型，两个 tsconfig 都查

# 验证
npm test                 # 跑全部单元测试
node --test tests/xxx.test.ts   # 跑单个测试文件
npm run check            # 最严的闸门：类型 + 测试 + 四项审计

# 打包（会真的产出安装包，慢）
npm run dist

# git 最常用的六个
git status               # 我改了哪些文件
git diff                 # 我具体改了什么
git diff --stat          # 改动的规模
git log --oneline -20    # 最近发生了什么
git checkout -- 文件      # 扔掉这个文件的所有改动（不可撤销）
git restore 文件          # 同上，新语法

# 找东西（在 D:\Aurora 下跑）
grep -rn "关键字" src/            # 搜内容
grep -rn "关键字" electron/       # 搜主进程
grep -rn "关键字" --include=*.tsx # 只搜某种文件
ls src/features                   # 看目录结构
```

**三条纪律**

1. **不确定就别 `git checkout`**——它真的会扔东西，而且没有回收站。
2. **改之前先看**：`git diff` 空着 = 干净的；不空 = 先搞清楚那是谁的改动。
3. **一次只改一件事**：改完立刻跑闸门，红了两分钟就能定位；攒一堆再跑，就得逐行猜。

## 六、一句话收尾

术语表不是用来背的。你会在做第 7 章练习册的时候，反复回来查同几个词——**查三次就记住了**，这是最自然的学习方式。
