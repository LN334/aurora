# 第 0 站：起步 —— 环境与命令行

> 目标：让这个项目在你机器上跑起来，并且你知道自己敲的每个字在干嘛。
> 预计：2–4 天，每天 1 小时。

---

## 一、要解决什么问题

编程的第一道墙不是语法，是**环境**。你不知道东西装在哪、命令为什么找不到、报错在说什么。

这一站只做四件事：认识终端、装对版本、把项目跑起来、会跑测试。

## 二、最小知识

### 1. 终端是什么

一个用文字跟系统说话的窗口。你敲一行，它执行一行，把输出打回来。

项目在 `D:\Aurora`。Windows 上有三种终端可选，**任选其一，别纠结**：

| 终端 | 打开方式 | 特点 |
| --- | --- | --- |
| Git Bash | 开始菜单搜 "Git Bash" | 本仓库的文档与脚本都按 bash 写，推荐 |
| PowerShell | `Win + X` → 终端 | Windows 自带，命令语法略不同 |
| VS Code 内置终端 | `Ctrl + 反引号` | 和编辑器在一起，最省事 |

下文命令按 bash 写。PowerShell 里 `ls`（别名）、`cd`、`cat` 也都能用，够你撑过这一站。

### 2. 六条命令，一辈子够用

```bash
pwd                 # 我在哪
ls                  # 这里有啥（-la 看隐藏文件与权限）
cd src              # 进去；cd .. 出来；cd /d/Aurora 一步到位
cat package.json    # 把文件内容打到屏幕上
grep -n "scripts" package.json   # 在文件里找某行（-n 显示行号）
clear               # 清屏（终端被刷乱时用）
```

再加一条**救命键**：`Ctrl + C`。任何命令卡住、刷屏、看起来死掉，按它。**这不是关机，是打断。**

### 3. 版本要对

```bash
node -v     # 本机实测：v24.22.2
npm -v      # 本机实测：11.19.1
git --version
```

项目用的是 **Node 24 + npm 11**。版本低了不一定报错，但会在某些地方诡异地失败。

装 Node 用官方安装包或 `nvm-windows`。**装完必须重开终端**，否则 `node` 还是找不到——这是因为 PATH 环境变量是终端启动时读的。这个坑每个新手都踩一次，现在你知道了。

### 4. npm 到底是什么

- `npm install`：照 `package.json` 里的依赖清单，把别人的代码下载到 `node_modules/`。
- `npm run <名字>`：执行 `package.json` 的 `scripts` 段里那条命令。
- `npx <工具>`：用一次性工具，不装进项目。

关键认知：**`npm run dev` 不是魔法，只是 `package.json` 里存的一行长命令的别名。**

打开 `package.json` 看 `scripts` 段（第 8–30 行左右），对照着读：

```json
"dev": "npm run build:electron && concurrently -k -n vite,electron -c cyan,magenta \"vite\" \"wait-on tcp:127.0.0.1:5173 && electron . --dev\"",
```

翻译成人话：

1. 先把 `electron/` 里的 TypeScript 编译成 `dist-electron/`（`build:electron`）
2. 同时起两个进程（`concurrently`），一个叫 vite 一个叫 electron，颜色分别是青色和洋红
3. `vite` 起开发服务器，端口 5173
4. `wait-on` 等到 5173 能连上了，才启动 `electron .`（`.` 表示用当前目录的 `package.json` 里 `main` 字段指定的入口）

所以 `npm run dev` 期间，**终端会同时吐两股日志**，青色的是前端，洋红的是主进程。看日志先看颜色。

### 5. 项目怎么跑起来

```bash
cd /d/Aurora
npm install     # 第一次要等；国内慢见下面的「坑」
npm run dev
```

看到窗口弹出来、有极光开屏，就成功了。

退出：终端里按 `Ctrl + C`，窗口一起关掉。

### 6. 测试是怎么跑的

```bash
node --test tests/crossfade.test.ts
```

本机实测输出（节选）：

```
✔ 0 means hard cut, not a 190ms fade (0.6552ms)
✔ the number in the setting is the fade length, not just a switch (0.1207ms)
✔ junk never reaches the audio clock (0.0892ms)
✔ an over-long value is clamped to the slider ceiling (0.0758ms)
ℹ tests 4
ℹ pass 4
ℹ fail 0
```

注意：**它不需要 Electron，不需要浏览器，不需要编译**。Node 24 能直接读 `.ts` 文件里的类型标注并忽略掉（这叫「类型擦除」）。这就是为什么这个项目把纯逻辑单独拆到 `electron/pure/` 和 `src/features/*/xxx.ts` 里——那些文件能被一条命令验尸。

全部测试：`npm test`。

### 7. git 只要三条（现在）

```bash
git status              # 我改了哪些文件
git diff                # 具体改了什么
git checkout -- .       # 反悔：把已跟踪文件全部恢复原样（会丢掉你的改动！）
```

`git checkout -- .` 是你这一周最常用的保命命令。练手改坏了就它。

**别急着学分支、rebase、stash。** 到第 7 章要开分支时再学，那时你已经有代码可改了。

### 8. 编辑器

VS Code（免费），装三个扩展就够：

- **ESLint**（如果项目有配置；本仓库没有 eslint 配置，可不装）
- **Error Lens** —— 把错误直接标在行尾，新手友好
- **Chinese (Simplified) Language Pack** —— 可选

VS Code 里按 `Ctrl + P` 输入文件名可跳转，`Ctrl + Shift + F` 全仓搜索。这两个键会占掉你一辈子 30% 的按键。

## 五、练手

**任务 A（10 分钟）**：把 `package.json` 的 `scripts` 里每一条抄到纸上（或笔记里），给每条写一句人话注释。`check` 那条特别值得抄，它一句话里串了六个动作。

**任务 B（20 分钟）**：不改代码，只改环境——
1. 删掉 `node_modules`（`rm -rf node_modules`），重新 `npm install`，计时。
2. 期间打开 `package.json` 看依赖清单，挑三个你认识的包名，搜一下它们是干嘛的。

**任务 C（15 分钟）**：用 `git log --oneline | head -20` 看最近的 20 个提交。注意提交信息的格式（`fix(player): ...`）。这是这个仓库的写作风格，第 7 章你要照着写。

## 六、这一站会踩的坑

**坑 1：`npm install` 卡在 Electron 二进制上**
Electron 的体积主要由一个 Chromium 二进制贡献，国内直连常失败。本仓库根目录有 `.npmrc`，里面已配了镜像。若仍失败，见 `README.md` 的「常见问题」。

**坑 2：命令找不到 `node`**
装完 Node 没重开终端。关掉终端窗口重开。

**坑 3：端口 5173 被占用**
`npm run dev` 会报 `strictPort`。多半是上一次的进程没死干净。找出来杀掉，或重启电脑（是的，这仍然是最快的办法）。

**坑 4：在 `D:\Aurora` 里跑打包产物起不来**
这个目录被挂了沙箱 ACL，`release\win-unpacked\Aurora.exe` 直接在原地跑会崩。要验打包版，先复制到 `%TEMP%` 或 `%LOCALAPPDATA%` 再跑。开发阶段用 `npm run dev`，暂时不会碰到。

**坑 5：以为终端报错就是自己搞坏了**
`npm run dev` 的日志里出现红字很常见（某个在线平台没登录、代理连不上）。判断标准只有一个：**窗口出来了没有、界面能不能用**。
