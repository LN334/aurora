# 界面规则

这份文档回答一个问题：改界面时哪些东西不能动，为什么。它不描述每个页面长什么样 —— 那看代码更快。

适配的是「一张会动的壁纸 + 一层玻璃」这个底子：背景永远在变，所以界面必须自己立得住，不能靠底色托。

## 七条硬规则

1. **一页只有一个标题。** 由外壳（`src/app/TitleBar.tsx` 与页面头）打印，页内不再重复。页内需要分段时用小标题，不用大标题。
2. **没有页内侧栏。** 曾经在在线页里做 268px 侧栏，结果像两个应用拼在一起。导航只在左栏一处。
3. **本地与在线共用同一套卡片与列表。** 形状一样，来源才用徽章与角标区分。各写一套意味着改一处忘一处。
4. **颜色只来自封面。** 主色由当前曲目的封面取出来，写进 `--accent-rgb`。不要在组件里写死颜色，也不要照截图取色 —— 截图里那个色是那一刻的封面。
5. **四个平台一起改。** 网易云、QQ、酷狗、汽水共用页面与列表；只改一家，等于埋了一个「这家能点、那家点了没反应」。
6. **交互不能走进死路。** 关掉一项功能时，界面上要留说明或回入口（例：首页四块全关时给一句「都关掉了」+ 回设置按钮）。不允许点了没变化。
7. **不用系统弹窗。** `window.confirm` / `alert` 一律换成应用自己的 Modal。

## 外壳

- 左栏固定 216px（收起后 64px），滚的是页面不是外壳。
- 一级项：现在 / 漫游 / 我喜欢的 / 最近播放 / 库（歌单·专辑·艺人·本机）/ 设置 / 我。库那四项是同一组，不拆成两个分区。
- 标题栏与搜索居中；搜索是动作不是目的地，全局只有一个输入框。
- 页面内容宽度上限由外壳给定，页面自己不再加一层 `max-width`（设置页例外，见下）。

## 首页的信息架构

顺序：问候 → **今天听什么** → 上次听到 → 四张快捷卡 → 推荐歌单 → 推荐专辑 → 最近新歌 → 最近听过。

排法的理由是「手上想干什么」优先于「有什么可以看」：

- 今天听什么（每日推荐）是唯一一个「现在就能放」的动作，放最上；
- 上次听到紧跟其后，「接着听」是第二高频；
- 四张快捷卡是导航，排在两个播放动作之后；
- 再往下才是需要往下翻的发现区。

首页**不解释推荐从哪来**。曾经在标题下加过「四家平台交叉推荐的 30 首 · 每天零点更新」，被明确否掉：机制说明是维护者视角，用户只关心放什么。平台来源只出现在推荐专辑标题旁那种小字里，且只列名字。

## 几个尺度（改之前先看）

| 区块 | 形态 | 关键尺寸 |
| --- | --- | --- |
| 今天听什么 | 左列文字 + 右侧可转封面墙 | 墙 660×220（窄屏 500×196），卡 128px，九张同屏 |
| 推荐歌单 | 六列方卡封面墙 | `repeat(6, minmax(0,1fr))`，窄屏 4 列 |
| 推荐专辑 | 一行横条，可左右翻 | 一屏 5 张，`calc((100% - 4 * var(--s3)) / 5)` |
| 最近新歌 | 左主推 + 右九行一屏 | 主推 320 方图；列表 `max-height: 378px`，行高 42px |
| 最近听过 | 八张窄卡 | 八列 145px，副标是相对时间 |
| 设置 | 单页玻璃板 | `max-width: 820px` 居中，整页一层 `backdrop-filter` |

封面墙为什么是九张：再多就缩到看不清封面里的字，再少就转不动。九张时相邻两张交叠约 55–63px，正好压住边缘又留出可辨的侧边。

## 颜色与玻璃

- 主色 `--accent-rgb` 由封面取色，界面里所有强调色从中派生（`rgb(var(--accent-rgb) / 0.6)` 这类）。
- 玻璃层的写法固定三件套：半透明底 + `backdrop-filter: blur()` + 1px 内描边。缺描边时，深色壁纸上的卡片会「浮」起来找不着边。
- 反例记一次：给幻灯片式的封面加按档 `filter: brightness()` 压暗，结果每张卡单独开合成层，快速滑动时跨档重建层，边缘错位、穿模更明显。压暗改用 1px 实描边与 z 序交代。

## 动效

三条铁律，都是踩过坑总结的：

1. **任何输入只改目标，不改位置。** 滚轮、键盘、点侧卡，都只写「目标位置」，位置由帧循环逼近。直接改位置会让事件间隔不均变成可见的抽搐。
2. **帧循环里不 setState。** 每帧重渲染会让九张卡一起 diff，抖。位置、透明度、z 序直写 `el.style`，只有「中心换到另一张」这种离散变化才让 React 重渲染一次。
3. **吸附用弹簧，不用线性插值。** 线性插值没有回弹，手感像拖动条。落位段用欠阻尼弹簧（`acc = gap * 190 - vel * 14`，ζ≈0.51），冲过去再弹回来。

常用常量（封面墙）：`STEP 88 / ARC 5 / DROP 22 / TILT 8.5 / SHRINK 0.09 / REACH 4`；远段速度模型 `GAIN 8 / SPEED_MAX 11 / REACT 26`。

还有两条别做：

- 不要给由帧循环驱动的元素加 CSS `transition: transform`。每帧换一个值，过渡每帧重启，永远追不上指针 —— 看起来就是「不丝滑」。
- 不要给每帧重绘的容器加 `mask-image` 或 `backdrop-filter`：整块每帧重新合成，帧率掉得看不出来，手感先坏。

进入/退出动效只碰 opacity 与 transform，且位移放在内层元素上：外层动画与 hover 上浮各用一个 transform，互不覆盖。

## 歌词

- 播放页与舞台共用一套纵深：中心行最亮最大，往外四档递减透明度与字号（`data-far` 0–4）。
- 行高必须跟着字号走：播放页 `LINE_RATIO = 2.588`（17px 字号 → 44px 行高）。只改字号不改行高，中心那句会顶出窗口。
- 原文与译文拆两行：`main` 一行、`sub` 小一号淡一档。判据在 `src/features/lyrics/line-parts.ts` 的 `splitLyricLine`（含「 / 」且前半段无中日韩字符才当译文）。
- 舞台的槽位高度用 `offsetHeight` 量，不能用 `getBoundingClientRect().height` —— 后者带 `transform: scale()`，量到的是缩放后的值，整列会只滚一半、顶端溢出。

## 文案

- 说人话，不说机制。错误要写「怎么办」，不是写异常名。
- 一句话只做一件事。设置项的说明写「关掉会怎样」，不写「本功能基于…」。
- 首次启动的引导只放能点的东西：一行一个开关，最多两页。说明性段落能删就删。
- 数量与时间统一：列表用 `mm:ss`，首页卡片的「最近听过」用相对时间（刚刚 / N 分钟前 / N 小时前 / N 天前）。

## 明确不做的

- 不做多套主题／皮肤。配色跟着封面已经够，再叠一层主题会打架。
- 不做页内滚动容器套滚动容器。
- 不在首页解释推荐机制、不在列表里解释接口状态。真要说明，放设置页。
